## 0. 发布顺序与约束

1. 发布前：生产库执行 4 个匿名策略配置 UPDATE，并刷新配置缓存。
2. 插件是否需要先发布，取决于线上实际情况，**执行前由 hydra 确认**。已有记录：plan 004 规划时插件尚未上架（版本 0.0.0，商店地址为占位），§4 的商店链接至今仍是占位 ID；提交 `82f1834`（插件 1.0.1）构建自 004 之后，当时 `WEBSITE.PRICING_PATH` 为 `/pricing/`；仓库里没有 1.0.1 是否上架的记录。按三种情况处理：
   - **从未上架**：不受约束；之后发布插件时用当前代码构建即可，常量为 `/ext-pricing/`；
   - **已上架 1.0.1 或其他 004 之后的构建**（常量为 `/pricing/`）：网站发布后它的升级入口会 404，必须先发布由当前代码构建的新插件版本，等审核通过后再发布网站；
   - **已上架 004 之前的构建**（常量为 `/ext-pricing/`）：仓库里没有这种情况的记录；hydra 确认属实则不需要重建插件。
3. 后端有 1 处代码改动：`subscription_service.py` 的订阅管理回跳地址由 `/pricing/` 改为 `/ext-pricing/`（新站没有 `/pricing/`），需随本次部署并重启；不迁移表结构。官网改版只带这 1 处后端改动，但部署 backend 时，HEAD 上其他已提交的后端改动也会一起上线，它们属于各自的发布，执行前要确认：自 004 实施提交 `1ffeedf` 之后，`backend/` 有 `e0ffb3c`、`0eead27`、`32f9524`、`eeba425`、`78cb4fa`（`git log 1ffeedf..HEAD -- backend`）。

## 1. 发布前：匿名策略配置

`config_init.sql` 只对全新环境生效（`INSERT IGNORE`，不覆盖已有行），已有环境必须手工执行同值 UPDATE。目标值以 `backend/src/app/init/sql/config_init.sql` 为准：

```sql
UPDATE config_public SET g_value = '2147483647' WHERE c_key = 'dl_anonymous_immediate_count';
UPDATE config_public SET g_value = '2147483647' WHERE c_key = 'dl_anonymous_total_count';
UPDATE config_public SET g_value = '4294967295' WHERE c_key = 'dl_anonymous_max_size_bytes';
UPDATE config_public SET g_value = '0'          WHERE c_key = 'dl_anonymous_wait_seconds';
```

执行后核对，4 行都必须存在且值与上面一致（UPDATE 命中 0 行说明该环境缺行，需改用 INSERT）：

```sql
SELECT c_key, g_value FROM config_public
WHERE c_key IN ('dl_anonymous_immediate_count', 'dl_anonymous_total_count',
                'dl_anonymous_max_size_bytes', 'dl_anonymous_wait_seconds');
```

约束：

- 大小上限固定 4294967295（4 GiB − 1），不要填更大的值：resource token 签发会拒绝大于 4 GiB 的资源。
- `dl_anonymous_dedup_seconds`、`dl_active_download_limit` 不变。
- 放开后匿名下载没有匿名次数门槛，大小仍受系统上限约束：size ≥ 4 GiB − 1 的资源匿名授权返回状态 3（口径见[匿名下载授权](../feat/002.下载功能/tech-匿名下载授权.md)），每设备并发 3 仍生效。

## 2. 发布前：刷新配置缓存

后端配置读取有进程内缓存（TTL 180 秒）。刷新方式：管理员登录后台后调用

```text
POST /api/admin/system-settings/config-cache/refresh
```

也可在管理后台「系统设置」的 config-cache 标签页操作。该接口只清空并重载**被调用的那个业务进程**的缓存；生产有多个业务进程或节点时，对每个进程各调一次，或等待 180 秒 TTL 自然过期，或重启进程。

## 6. 回滚要点

本次是网站首次上线，没有上一个生产版本可回退。

- **网站**：回滚即网站下线，两种方式任选其一（生产 vhost 为 `/usr/local/nginx/vhost/vimeo-web.conf`，root 固定为 `/data/vimeo-download/website/current`）：
  1. 删除站点：`rm /usr/local/nginx/vhost/vimeo-web.conf && nginx -t && nginx -s reload`。首次部署时这个 vhost 是新建的，删除即回到部署前的状态；
  2. 删除 `current` 软链（`/data/vimeo-download/website/current`）：Nginx 的 root 不存在后，全站返回 404。
- **插件**：网站下线后，无论哪个插件版本，升级入口都不可用，与常量无关；回滚时不需要改发插件。
- **后端**：回跳地址回滚到 `/pricing/` 没有意义：新站没有该路径，会 404。网站下线时后端可保持现状，不必回滚。
- **配置**：是保持放开，还是改回，取决于是否仍要对外提供匿名下载（网站下线后这些配置没有访问方，保持放开也无影响）。要改回时：把 4 个值改回发布前记录的值（发布前先 `SELECT` 留档；`config_init.sql` 的旧种子为 2 / 3 / 314572800 / 300），再刷新配置缓存。

# 001 · Free 额度与首日免费

## 目标

1. Free 档每日下载上限从 5 次改为 3 次。
2. 新增首日免费：作用域首次下载当天不限次，自次日起按档位上限。

## 依赖 plan

无。与 `@../../006.订阅系统/plans/006.好评奖励领取资格去重.md` 互相独立，可并行；两者共用同一套 uid 构造 helper 与「普通 INSERT + 捕获唯一键冲突」的写入写法。

## 改动范围

1. Free 上限常量、生产商品配置数据与部署 runbook 同步改为 3。
2. 新增首日事实 MySQL 表与 Model 登记。
3. `QuotaService` 增加首日判断与幂等补登记能力，`set` 增加设备标识参数。
4. 三个入口负责传入设备标识，保证登录用户同时具备账号与设备两个维度。
5. 下载扣减与订阅状态两个入口共用同一判断，保证展示与行为一致。
6. 真实 MySQL 测试覆盖首日、跨天、维度补记与失败口径。

## 设计要点

- 首日事实落 MySQL，不用 Redis：Redis 数据受淘汰、重启与运维清理影响，丢失会导致首日重置。
- **`QuotaService.set` 增加 keyword-only 可选参数 `device_id`**：`set(u_id, quota_type, number, *, device_id=None)`。不引入 `QuotaScope` 之类的值对象（多一层概念、零收益）。当前签名只接收单个 `u_id`，登录后设备标识在 API 层就丢了。三个出口负责传入：`quota_client.py`（`/quota/check`）、`subscription_client.py`（`/subscription/status`）、`auth_client.py` 的 `/me` 端点（后两者都调 `subscription_status_service.build_status_data`，该方法同样加 keyword-only `device_id`）。`/me` 与 `/subscription/status` 是两个独立出口，只改其一会让账号摘要在老设备上显示不限次而下载接口限额。Redis 额度 key 的 `u_id` 作用域保持原样不变，新增的设备标识只服务首日判定。
- `u_id` 与 `(user_id, device_id)` 的推导关系**保持现状**，不在本次收敛：匿名分支的 `validated_device_id()` 在标识缺失时会抛设备错误，把它搬进 service 会改变既有错误面。
- **首日判定必须落在类型分派之后、订阅查询与上限解析之前**，且只对 `EXTENSION_DOWNLOAD` 生效。顺序的含义是「不被订阅查询或商品配置异常连累」（判定自身读首日表的动作不在此限）；非 `EXTENSION_DOWNLOAD` 类型完全不进入该分支，否则既有单测 `tests/test_server/api/test_web_quota_api.py`（monkeypatch 掉上限解析后直接调 `set(WEB_DOWNLOAD)`）会开始访问真实 MySQL。
- **每次 `EXTENSION_DOWNLOAD` 下载都幂等补登记所有可用维度**，不是只在命中首日时登记；补写发生在**判定之后、返回之前**，且**非首日路径同样补写**（"老账号 + 新设备"正是靠这一步补上设备行）。否则老账号在新设备会漏记设备维度、新账号在老设备会漏记账号维度，用户退出登录或换设备后能重获首日。补登记不覆盖已有维度，`ymd` 保持首次值。
- **"复用同一次查询结果"是可检查约束**：判定方法一次返回「已有记录的 scope 集合 + 是否首日」，补登记只消费这个集合去插入补集，判定方法内部**不得出现第二条 SELECT**。表行数上界约为「用户数 + 设备数」，不随下载次数增长；稳态（两个维度都已登记）只有一次等值读、零写入。
- **不为首日判定加 Redis 缓存**：判定粒度是业务日、跨天失效，缓存只会引入新的不一致面。
- 因为补登记每次下载都跑，登记写失败不再是"永久首日"，而是"本次抖动、下次下载自愈"。
- 命中首日即直接返回不限次结果，不进入上限解析与 Lua 扣减；API 层不持有额度规则、不重拼响应体。
- 维度：匿名只查 `device`；登录查 `user` + `device`，任一维度存在早于今天的记录即非首日。
- 判据按业务日期，不按记录是否存在：无记录 = 首日尚未开始；记录 `ymd == 今天` = 首日；任一记录 `ymd < 今天` = 非首日。
- **失败口径：首日判定是尽力而为的增强，不是任何主流程的前置条件**。判断或登记任一失败都跳过首日分支、继续走正常额度，只记 `logger.error(exc_info=True)`，不把异常抛给 API 层。宁可让个别用户当天按 3 次计，也不能让 MySQL 抖动拦住下载——用户直接被拦住会流失，多计一次只是少一次优惠。
- **展示侧同样降级**：`/subscription/status` 与 `/auth/me` 的首日判定失败时按"非首日"展示（返回档位上限），不向上抛异常。额度展示错一次无所谓，但这两个接口分别是插件刷新额度、校验身份的入口，不该因为首日判定而失败。

## 表规格

表名 `user_first_day`，与既有 `user_*` 家族一致。

| 列 | 类型 | 约束 | 语义 |
| --- | --- | --- | --- |
| `uid` | `VARCHAR(32)`，`collation=utf8mb4_bin` | PK | 由唯一 uid 构造 helper 生成 |
| `ymd` | `INT` | NOT NULL | 首个下载日的业务时区 `YYYYMMDD`，判定列 |
| `value` | `VARCHAR(128)` | NOT NULL | 带前缀原值（`userid:123` / `Device-Id:xxx`），仅供人工排查与迁移核对，不参与任何业务查询 |
| `created_at` | `BIGINT` | NOT NULL | 记录创建时间（毫秒时间戳），与 `counter_*` 家族口径一致 |

`uid` 用自然键做主键，不再另挂唯一键；`collation=utf8mb4_bin` 是硬要求——默认 `_ci` 排序规则下 `abc` 与 `ABC` 相等，会掩盖 Python 与 MySQL 侧的哈希大小写漂移。`value` 不建索引。索引行尾需按 `spec-index.md` 注释说明服务的查询。

uid 由唯一 helper 构造，与 `@../../006.订阅系统/plans/006.好评奖励领取资格去重.md` 共用同一套前缀与算法约定：

```text
sha256("userid:{user_id}").hexdigest()[:32]
sha256("Device-Id:{device_id}").hexdigest()[:32]
```

补登记采用普通 INSERT + 捕获唯一键冲突，**不用**受影响行数判断（MySQL affected-rows 受 `CLIENT_FOUND_ROWS` 影响，会把"行已存在"报成 1 行）。

## 验收标准

- Free 档上限为 3 次/天，代码与生产数据一致。
- 作用域首次下载当天不限次，且不写当日额度 key；次日恢复 3 次/天。
- 登录用户在同一设备换账号后仍判非首日；匿名下载后登录也不会重获首日。
- **老账号在新设备下载后，该设备维度被补记**：次日退出登录继续用该设备仍判非首日。
- **新账号在老设备下载后，该账号维度被补记**：**次日**起换新设备仍判非首日。当天换新设备仍是该账号的首日——它今天确实是首次下载，补记今天即正确语义，不需要伪造历史日期。
- 补登记不覆盖已有维度，`ymd` 保持首次值。
- `/quota/check`、`/subscription/status` 与 `/auth/me` 三处首日口径一致。
- 首日模块异常**不直接导致请求失败**：判断或登记失败时跳过首日分支，后续按普通额度与既有错误规则处理，并留下可定位的错误日志。
- 覆盖"普通额度当天已用满"的场景：此时首日模块异常按正常限额拒绝，属既有规则，不视为回归。
- 不新增 Redis key、不加锁、不加 Lua、不新增第三方依赖。
- `value` 列无索引、不被业务读取。

## 已知限制

- 存量免费用户没有首日记录，上线后首次下载当天算首日，会白得一天不限次；不做数据迁移。
- 匿名设备清扩展数据即换新作用域，重获首日。
- 付费用户首日同样登记，订阅到期后不再享有免费首日。
- 已登录用户省略 `X-Device-Id` 时无法登记设备维度，只按账号维度判定。
- 共享浏览器 profile 上只要更早某天下载过，之后任何新账号都拿不到首日。
- 旧插件仍把首日不限次显示为 Unlimited。新版插件将订阅与额度分开判断，展示规则见 [额度查询与前端](../tech-额度查询与前端.md#3-插件端额度展示与拦截)。

## 风险与恢复

- 首日判断落在下载链路，MySQL 抖动时会跳过首日分支、按正常额度扣减：用户照常能下载，当天可能少一次首日优惠，并留下可定位的错误日志。
- 回滚方式为回退 `set` 的首日分支与设备参数并下线表读取；已写入的首日事实不回退。

### 遗留

- **Free 档生产商品配置未改**：已交付 011 runbook 的 seed（`daily_limit=3`）与存量行 `JSON_SET` 语句，但未执行。本地配置库同样未写，因此真实库中 Free 的实际上限目前仍以配置值 `5` 为准，发布前必须按 runbook 执行。
- **展示侧首日降级无测试证据**：真实可达且非破坏性的触发方式不存在（破坏性 DDL 或 mock DB 分别违反测试隔离与 spec-test-server），架构师裁决为已知限制，行为仅由代码契约与错误日志保证。
- **登记失败用例的输入只在 service 层可达**：触发失败的超长设备标识被 API 层 `X-Device-Id` ≤64 校验挡住，该用例不构成 HTTP 入口的验收证据。
- `_build_first_day_scopes` 的调用按架构师裁决移出 `try`，只保留 DB 步骤（读表 + 补登记）的降级 guard。

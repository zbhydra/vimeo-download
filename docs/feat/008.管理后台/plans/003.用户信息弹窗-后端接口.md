# 003 · 用户信息弹窗后端接口

## 目标

为管理后台提供通用用户信息弹窗所需的只读接口:用户 profile 聚合、最近下载分页和订单分页。

## 依赖 plan

无。前端接入依赖本 plan 完成。

## 改动范围

- 新增 `backend/src/app/api/admin/admin_users.py`
- 新增 `backend/src/app/services/admin_user_profile_service.py`
- 新增 `backend/src/app/schemas/admin_user_schema.py`
- 修改 `backend/src/app/main.py` 注册 admin users router
- 新增 `backend/tests/test_server/api/test_admin_user_profile_api.py`

## 文件或模块责任

- API 层:校验 `user_id` / 分页参数,返回统一 `{code,data,msg}`。
- service 层:聚合读取 `users`、Credits 余额、订阅原始过期时间、`user_download_records` 分页、用户全部订单分页。
- schema:定义 admin 用户 profile 与下载列表响应字段,字段全部有注释。
- 测试:覆盖鉴权、profile 成功、用户不存在、下载分页、订单分页、空列表。

## 接口验收

- `GET /api/admin/users/{user_id}/profile` 返回用户基础信息、`credits.balance`、`subscription.has_subscription`、`subscription.expires_at`。
- `has_subscription` 只在 `expires_at > now_ms` 时为 true;已过期时 false 但返回原始 `expires_at`。
- `GET /api/admin/users/{user_id}/downloads` 按 `created_at desc, id desc` 返回指定用户的下载记录,支持 `page` / `page_size`。
- `GET /api/admin/users/{user_id}/orders` 按 `created_at desc, id desc` 返回指定用户全部订单,不按成功/失败/状态过滤。
- 两个接口不返回密码、token、验证码、JWT、支付敏感数据。
- 不新增表、字段、索引,不执行 schema 同步。

## 风险与回滚

- 风险:单个用户下载记录极多时分页排序会有额外开销。当前是 admin 低频排查接口,且按用户过滤可接受。
- 风险:订阅配置异常不应影响弹窗,所以接口只读 `user_subscriptions` 原始过期时间,不读取商品配置。
- 回滚:移除 router 注册和新增文件即可,不涉及数据库变更。

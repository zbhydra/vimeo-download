# 001 · 数据分析 - 后端聚合接口执行计划

> 配套需求与完整口径见 `@../feat.md`、`@../tech-数据分析.md`。本计划只列执行步骤、责任边界、验收与回滚。
> **依赖**:无,可与 `@002.数据分析-前端页面与组件.md` 完全并行。前端联调依赖本计划产出的 4 个接口契约(已在 tech 文档定稿,前端可先按契约 mock)。

## 目标

交付 4 个 admin 只读聚合接口(`/api/admin/download-analytics/*`),支撑数据分析菜单的四个标签页,并为时间范围查询补 `created_at` 索引。

## 改动范围

| 文件 | 操作 | 责任 |
| --- | --- | --- |
| `backend/src/app/services/admin_download_analytics_service.py` | 新增 | 桶定义常量 + 4 个聚合方法 + 模块级实例 |
| `backend/src/app/api/admin/admin_download_analytics.py` | 新增 | `APIRouter(prefix="/download-analytics")` + 4 个 GET 路由 + 参数校验 |
| `backend/src/app/main.py` | 修改 | `_include_business_routes` 注册新 router |

## 执行步骤

### 1. service(`admin_download_analytics_service.py`)

- 模块顶部常量:`_MIB = 1024*1024`、`_GIB = 1024*_MIB`;`SIZE_BUCKETS`(12 桶的 key/label/区间定义,与 tech「资源大小分桶规则」表格一致);`BUCKET_ORDER`(固定展示顺序)。
- 类 `AdminDownloadAnalyticsService`,4 个 `async` 方法(签名 `(self, from_ms, to_ms)`,**方法内部 `async with get_async_session() as db:` 自管 session** —— 与 `dashboard_service` 等项目惯例一致;`get_async_session` 是 `@asynccontextmanager` 非 Depends 生成器,此写法不引入依赖注入):
  - `get_resource_distribution(self, from_ms, to_ms) -> list[dict]` —— 返回 12 桶,每桶 `{key, label, paid_count, total_count}`,按 `BUCKET_ORDER` 补齐空桶为 0。
  - `get_top_users(self, from_ms, to_ms) -> list[dict]` —— 返回至多 20 条 `{user_id, paid_count, total_count}`。
  - `get_summary(self, from_ms, to_ms) -> dict` —— 返回 6 个标量(见 tech 接口 §3)。
  - `get_user_geo(self, from_ms, to_ms) -> list[dict]` —— 返回 `{country, count}`,`country` 空值归 `"unknown"`,按 count 降序。
- 4 段聚合 SQL **完全照 tech「聚合逻辑」实现**(注意全限定 `UserDownloadRecordModel.xxx` / `UserModel.xxx`;资源分布 CASE 第一个 WHEN 同时匹配 `IS NULL` 与 `= 0` 归 `unknown`)。
- 模块底部 `admin_download_analytics_service = AdminDownloadAnalyticsService()`。**不用 `@singleton`**(见 `@docs/references/specs/spec-python.md` §9)。

### 2. API(`admin_download_analytics.py`)

- `router = APIRouter(prefix="/download-analytics", tags=["admin-download-analytics"])`。
- 4 个 `GET` 路由(`/resource-distribution`、`/top-users`、`/summary`、`/user-geo`),`Query` 参数 `from_ms: int`、`to_ms: int`,`Depends(get_admin_user)`。
- 参数校验在路由层:`from_ms < to_ms` 否则抛**定位级**错误(示例 msg 见 tech「时间参数」)。
- 注入 `AsyncSession`,调对应 service 方法,`ResponseUtils.ok(data)` 返回。

### 3. main.py 注册

- 在 `_include_business_routes` 内,仿 `admin_dashboard_router` 的挂法 `include_router(admin_download_analytics_router, prefix="/api/admin", tags=["admin"])`。

## 验收标准

- 正常时间区间下,4 接口返回结构、字段名、桶顺序/数量与 tech「接口」一致(资源分布恒为 12 桶;排名 ≤20;summary 恰好 6 标量)。
- `from_ms >= to_ms` 返回参数错误(可定位的 msg);区间无数据时各接口返回 0/空数组,**不抛异常**。
- 手工对账:任取一区间,`credits_cost > 0` 计数 = summary 的 `paid_download_count`;资源分布 12 桶 `total_count` 之和 = summary 的 `total_download_count`。
- `black` + `ruff` + `mypy` 全通过。

## 风险与回滚

- 新增文件独立,无存量逻辑改动;回滚 = 删 2 个新文件 + `main.py` 去掉 include 行。
- 风险点:聚合 SQL 的 `case` / `func.count(func.distinct(...))` 写法以 tech 为准,勿擅自简化;`@singleton` 勿从 `dashboard_service` 误抄。

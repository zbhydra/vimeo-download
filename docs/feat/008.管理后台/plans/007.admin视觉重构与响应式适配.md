# 007 · admin 视觉重构与响应式适配（Elera 基线）

> 执行计划：按 `@../tech-视觉基线.md` 的设计合同改造 admin 视觉，并完成手机（<768）与平板（768–1023）适配。
> 现状事实与证据：本计划所引用的源码位置均已于 2026-10-08 核实。

## 1. 目标与非目标

**目标**：admin 全站换肤为 Elera 视觉基线（暖灰画布 + 白卡软阴影 + 草绿 accent + 13px 密度）；侧栏分组导航；平板/手机三视口可用；既有 e2e 全绿。

**非目标**：不换组件库；新增依赖仅 `@fontsource-variable/inter`（已获批）；不引入图表库；不做暗色主题；不自绘侧栏/顶栏组件（NMenu/NLayoutSider 主题化即可，保住 e2e 的 `getByRole("menu")`）；不改后端；不修既有硬编码列名（`id`/`url`/`ID`）与 i18n locale 硬编码 zh-CN（范围外，已记录）。

## 2. 依赖

- 无外部依赖。P2 依赖 P1 的 token；P3 依赖 P1；P4 依赖 P2 的断点常量。
- P3 内部各视图互不依赖，可并行。

## 5. 风险与已知事项

| 风险/事实 | 处置 |
| --- | --- |
| e2e 几何断言对密度敏感（`orders.spec` 筛选行几何、`dashboard.spec` 列顺序、`layout-navigation.spec` 侧栏标题） | 样式改动导致期望值失效时按维护更新测试期望，行为合同不变 |
| `layout-navigation.spec:158` 依赖 NMenu 的 `role="menu"` | 不自绘侧栏即消除该风险（P2 走 NMenu 主题化路线） |
| elera 调研稿（scratch）与真实代码有出入（菜单 7 项而非 9、无 TgClients/ChannelSettings、Settings 单视图、NConfigProvider 已在 App.vue、Naive 无 `tdPadding`/`Modal.borderRadius` 键） | 本计划与 tech-视觉基线均已按真实代码与 2.44 源码修正；scratch 稿仅作截图参考 |
| 手机端既有 bug：Orders 详情抽屉固定 720px 溢出 | P4 修复 |
| 参考方表格密度（单元格上下 10px）使 admin 宽表同屏行数减少 | 按基线执行，属预期取舍；验收时重点确认滚动与分页体验 |
| CSS 断点现状不一（767/760/640/560/960） | 布局形态切换统一走 useViewport 两档；内容网格局部断点保留（合同见 tech-视觉基线 §4.1） |
| fixed 列边界在 scroll=0 时有 1px 级残字（naive sticky 固有，滚动即消失；证据 `docs/scratch/admin-restyle/u4/service-nodes-1280.png`） | 已知视觉残留，接受；彻底消除需调列宽或去 fixed，范围外 |
| responsive.spec「同名节点复用」分支仅逻辑审读、未实测命中；且节点 name 无唯一约束，并发执行同一后端仍可能重复建节点 | 复用分支下次运行自然覆盖；e2e 本地单实例 + spec 内串行，实际风险低，接受 |

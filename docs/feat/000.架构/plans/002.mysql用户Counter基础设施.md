# 002 · MySQL 用户 Counter 基础设施

## 目标

按 `@../tech-counter.md` 建立 DAILY、MONTHLY、LIFETIME 三周期 MySQL 用户 Counter，保留三个生产 Demo ID，并清理无业务调用的旧 Redis Counter API 与 Extension wrapper；不接入任何现有业务。

## 依赖 plan

无。

## 阶段一：注册表、时间与数据模型

### 改动范围

- 重写 `backend/src/app/constants/counter.py`：固定周期、Counter ID、定义与生产注册表。
- 在 `backend/src/app/utils/time.py` 增加当前 `YYYYMMDD` / `YYYYMM` 整数工具。
- 新增 daily、monthly、lifetime 三个 Model，并在 `app.models` 注册。

### 验收标准

- `9001/9002/9003` 分别稳定映射 DAILY/MONTHLY/LIFETIME。
- 三表字段、comment、PK/UK 与技术规格一致。
- 不存在外键、额外索引或清理任务。

## 阶段二：Service

### 改动范围

- 重写 `backend/src/app/services/counter_service.py`。
- 实现 `add/get/get_list`，使用模块级实例，不使用依赖注入或 `@singleton`。
- `add` 拒绝零和负增量，按固定周期执行一条 MySQL 原子 upsert 和一次 commit。
- `get_list` 按周期分组，最多查询三张表，缺失值补 `0`。

### 验收标准

- 三种周期都通过同一接口使用，调用方不传 session。
- 未知 ID、非法增量、数据库错误直接抛出。
- 不存在锁、重试、幂等、流水、补偿、reset 或减计数接口。

## 阶段三：删除未使用的旧入口

### 改动范围

- 删除 `backend/src/app/api/client/counter_client.py` 及 `main.py` 路由注册。
- 删除 `extension/src/core/api/counter/`。
- 删除 Extension Counter endpoint 常量、导出和示例注释。
- 保持 `quota_service`、`/api/client/quota/check`、`/api/client/subscription/status` 及插件实际调用不变。

### 验收标准

- 全仓库不存在旧 `/api/client/counter/**` 调用或定义。
- 插件下载仍调用 `/api/client/quota/check`，额度展示仍调用 `/api/client/subscription/status`。

## 阶段四：真实测试与结构同步

### 改动范围

- 新增真实 MySQL Counter service 测试，直接使用三个生产 Demo ID。
- 每个测试标记 `@pytest.mark.real` 与 `@pytest.mark.asyncio`，声明真实 MySQL 依赖；MySQL 或三张 Counter 表不可用时分别使用 `REAL_MYSQL_UNAVAILABLE` / `REAL_SCHEMA_UNAVAILABLE` skip code。
- 使用 `test_run_id` 派生每次运行独占的高位 `user_id`；`_CleanupState` 记录三表精确清理条件，teardown 只删除本次数据，不改配置表或其他业务数据。
- 运行 schema sync 创建三张表并核对最终索引。

### 验收标准

- 初始值、连续累加、三周期混合读取、零/负增量拒绝、未知 ID、空列表与重复 ID 全部通过；`get_list` 无数量上限，因此不设计超数量拒绝用例。
- 同一用户、同一桶和同一 Counter ID 的真实并发 add 最终总和精确。
- 同一自然桶内 upsert 不产生重复行。
- `information_schema.statistics` 只显示每表 PK 和技术规格定义的 UK。
- 实施后在 `tech-counter.md` 回填三处真实 WHERE 的源码文件与行号，Model UK 行尾注释写明服务的 `add/get_list` 查询。

## 阶段五：同步现状文档

### 改动范围

- 实施完成后更新 `tech-数据库.md` 的现有 Model 文件树。
- 实施完成后把 `tech-extension.md` 的 Counter/Quota 双接口现状改为单一 Quota 接口。
- 更新架构 changelog 的实际产出与验证结果。

### 验收标准

- `tech-数据库.md` 与 `tech-extension.md` 描述的文件和接口均能在实施后源码中找到，且不存在已删除旧入口。

## 文件或模块责任

- `constants/counter.py`：稳定 ID、周期与静态注册表。
- 三个 `counter_user_*_model.py`：周期各自的数据约束。
- `counter_service.py`：唯一 MySQL Counter 读写入口。
- `utils/time.py`：复用唯一业务时区计算桶编号。
- API 与 Extension 清理：只删除静态检索确认无业务调用的旧 Counter 表面。

## 风险与恢复

- schema sync 创建的新表不会由代码回滚；若放弃功能，先确认无业务数据，再人工删除三张 Counter 表。
- 删除旧 Counter HTTP 路由后，仓库内当前插件不受影响；恢复时可从版本控制取回旧路由和 wrapper，但不得让 Redis Counter 与 MySQL Counter 共用同一 service/constants 名称。
- Counter 与未来业务不在同一事务内，允许少量多记或少记；不增加补偿或对账。

# 001 · Website 首次访问 mark-log

## 目标

在 website 确认 `homepage_first_opened_at` 且本机尚未提交过首次访问事件时,异步上报 `web_first_opened`,并同时写 SLS 与后端 `mark_logs`。

## 依赖 plan

无。

## 改动范围

- `website-shared/src/homepage-runtime/device.ts`:返回首次打开时间与持久化结果。
- `website-shared/src/homepage-runtime/first-opened-mark.ts`:新增 website 首次访问上报入口与提交标记。
- `website/src/layouts/Layout.astro`:只在主站启动首次访问上报。
- `website-shared/src/homepage-runtime/mark.ts`、`website/src/scripts/homepage/mark.ts`:补 `web_first_opened` 类型。
- `backend/src/app/constants/mark.py`:补 `WEB_FIRST_OPENED`。
- `backend/src/app/services/dashboard_service.py`:把 `web_first_opened` 放在 Dashboard 动态打点列首位。
- 文档与测试同步更新。

## 文件或模块责任

- 首次时间由 `homepage_first_opened_at` 负责;`web_first_opened` 是否已经发起提交由 `homepage_web_first_opened_submitted_at` 负责。
- `web_first_opened` 只由 website 布局启动。
- `localStorage` 写入成功时上报空 `mark_msg`。
- `localStorage` 不可用或写入失败时仍上报,`mark_msg` 为 `{"reason":"localStorage_unavailable"}`。
- 后端复用 `/api/client/mark/record` 与 `mark_logs.first_opened_at`,不新增表字段。

## 验收标准

- 新设备第一次打开 website 后产生一条 `web_first_opened` SLS 日志,并尽力写入后端 `mark_logs`。
- 已存在 `homepage_web_first_opened_submitted_at` 时不重复上报。
- 已存在 `homepage_first_opened_at` 但缺少提交标记时补提交一次。
- `localStorage` 不可用时仍上报,且 `mark_msg` 标记 `localStorage_unavailable`。
- Admin Dashboard 表格动态列第一列为 `web_first_opened`。

## 风险与回滚

- 风险:用户禁用持久化存储时无法跨刷新去重,可能重复产生 `web_first_opened`。当前按产品口径接受,用 `mark_msg.reason` 区分。
- 风险:上线后已经有 `homepage_first_opened_at` 但没有提交标记的浏览器,会补交一次 `web_first_opened`。
- 回滚:移除首次访问上报入口与 `WEB_FIRST_OPENED` 枚举,Dashboard 顺序恢复即可;无数据库迁移。

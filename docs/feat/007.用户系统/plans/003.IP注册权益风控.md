# 003 · IP 注册权益风控

## 目标

同一 IP 在配置窗口内注册账号超过允许数量后,新账号仍可正常创建、登录和使用产品,但不送注册 Credits,也不给可领取的签到活动。

## 依赖 plan

无。

## 改动范围

### 后端数据模型

1. 新增 `backend/src/app/models/user_ip_register_model.py`。
2. 字段:
   - `user_id`: bigint PK。
   - `ip_address`: varchar(64),注册时客户端 IP。
   - `created_at`: bigint,毫秒时间戳。
3. 索引:
   - `idx_user_ip_registers_ip_address(ip_address)`,服务注册/签到按 IP 统计窗口内注册数。
4. `backend/src/app/models/__init__.py` 导出新 model。

### 配置

1. `config_public` 新增 key:`registration_ip_benefit_guard`。
2. value:

```json
{
  "window_seconds": 86400,
  "max_registrations": 3
}
```

3. 配置缺失或非法时风控关闭。

### 后端 service

1. 新增 `backend/src/app/services/user_ip_register_service.py`,模块级实例 `user_ip_register_service`。
2. 提供:
   - `record_register_best_effort(user_id, ip_address)`:插入失败只记日志。
   - `is_registration_bonus_allowed(ip_address)`:注册前按窗口统计,判断本次是否可发权益。
   - `_load_guard_config()`:调用 `config_public_service.get("registration_ip_benefit_guard")`,用 Pydantic model 校验配置;配置缺失或非法时返回关闭态。
3. 不新增依赖注入。

### 注册接线

1. `user_service.create_user_with_registration_bonus()` 和 `create_user_without_password_with_registration_bonus()`:
   - 创建用户前读取 `is_registration_bonus_allowed(register_ip)`。
   - 创建用户后 best-effort 写 `user_ip_registers`。
   - 可发时调用 `_add_registration_credits`;不可发时跳过。
   - 不可发时立即调用 `user_checkin_service.create_expired_campaign(user_id)` 插入已过期 campaign。
2. Google 首次注册、邮箱验证码首次注册、密码注册共用这两个方法,不在 API 层重复逻辑。
3. `register_ip` 为空时风控放行。
4. 已过期 campaign 插入不做幂等、不做补偿;插入失败允许影响本次注册接口返回。

### 签到接线

1. `user_checkin_service` 新增 `create_expired_campaign(user_id)`。
2. `_get_or_create_campaign()` 改为先按 `user_id` 读取最新一条 campaign;存在则直接返回,即使已过期也不新建。
3. 只有完全没有 campaign 时才创建正常活动。
4. `claim_daily_checkin()` 直接调用且没有 campaign 时仍按原规则补创建正常活动。

## 验收标准

1. `config_public.registration_ip_benefit_guard = {"window_seconds":86400,"max_registrations":3}` 时,同一 IP 第 1-3 个新账号获得注册 Credits,第 4 个及之后新账号不获得注册 Credits。
2. 命中风控的新账号登录成功后 `credits_balance` 不含注册赠送。
3. 命中风控的新账号注册成功后,数据库存在一条已过期 `user_checkin_campaigns`。
4. 命中风控的新账号调用 `/api/client/checkin/entry` 返回活动已结束,不展示可领取签到奖励。
5. 命中风控的新账号直接调用 `/api/client/checkin/claim` 返回活动已结束错误,不发 Credits。
6. `user_ip_registers` 插入失败不影响注册成功。
7. 清理 `user_ip_registers` 后,后续判断按剩余数据重新计算;已插入的过期 campaign 不受影响。
8. 配置缺失或非法时,注册赠送和签到保持原行为。

## 风险与回滚

- 风险:已过期 campaign 插入失败后,该用户可能没有签到封禁记录。接受本次请求失败,不做补偿任务。
- 风险:插入辅助表失败会导致后续判断偏宽。接受该简单边界。
- 风险:只用 `ip_address` 单列索引,大 IP 数据量下窗口统计可能多扫一些行。该表允许清理,先不加联合索引。
- 回滚:删除注册赠送前的风控判断和签到创建前的过期 campaign 分支;保留 `user_ip_registers` 表不影响主流程。

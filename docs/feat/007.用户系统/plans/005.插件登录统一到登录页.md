# 005 · 插件登录统一到登录页

## 目标

插件内所有登录都在插件登录页 `ext-login.html`（扩展标签页）完成，Google 按钮与邮箱表单同页。popup 与插件订阅页不再承载任何登录界面。登录页与 website 无关。

## 背景

当前未提交改动已实现「popup 弹窗保留 Google，邮箱转插件登录页」：

- popup 失焦即被 Chrome 销毁，验证码步骤必须在标签页完成。
- 因此出现了两套登录界面：`LoginPanel` 有 `tab` / `inline` 两种模式，`handoff` 事件，以及 `GoogleLoginService` 中 `callerIsPopup`（按 RPC `context.tabId` 判定）的转交分支。

本计划在这批未提交改动之上继续收敛，把登录只留一个承载面。

## 核心方案

1. **统一入口**
   - `core/composables/loginModal.ts` 收敛为一个入口函数 `openLoginPage(source)`：先记一次 `login_click`，再打开 `ext-login.html?source=`。
   - 文件按职责改名，名称由执行者决定。
   - 打开方式：
     - popup 调用时新开标签页；
     - 插件订阅页（`PremiumView` 的 `page` 模式）调用时，当前标签页跳转到登录页，避免登录后多出一个订阅页标签。
   - 删除以下内容：
     - 弹窗可见状态、`hostMounted` 与「无登录面退回官网 pricing」分支；
     - `closeLoginModal`、`notifyLoginCancelled`、`dismissLoginModal`、`adoptLoginSource`；
     - 模块级 `loginSource`。

2. **登录页**
   - 删除 `popup/components/LoginModal.vue`。
   - `LoginPanel` 只服务登录页：
     - 删掉 `emailEntry`、`expandEmail`、`verifyEmail` 三个 prop 和 `handoff` 事件；
     - 删掉 `emailExpanded`、`showEmailForm`，以及由 `verifyEmail` 初始化状态的分支；
     - 邮箱表单常驻在 Google 按钮下方；
     - Google 返回 `email_verification` 时，保留原地写入邮箱、切到验证码步骤的赋值；
     - `source` 通过 prop 传入，打点函数显式接收 `source`。
   - 全局 `getLoginSource` 随模块级 source 一起删除。
   - popup `App.vue` 与 `PricingApp.vue` 的 `handleLoginSuccess` 失去宿主，一并删除。
   - 界面按下文「UI 设计」实现。文件位置与是否保留 `loginTheme.ts`，由执行者按最简原则决定。

3. **登录成功去向**
   - 去向由 `source` 决定，不再依据是否存在待购商品：
     - **购买入口**（`popup_upgrade_now` / `popup_quota_counter` / `upgrade_modal`）：`location.replace` 到插件订阅页。订阅页的 `PremiumView` 恢复待购商品并继续下单（现有逻辑）。
     - **`popup`**（顶栏登录）：清除 `STORAGE_KEYS.PENDING_PREMIUM_PURCHASE`，展示成功提示。
   - 为什么清待购：
     - 原先关闭弹窗会派发 `vdl-login-cancelled`，由 PremiumView 清待购；改为标签页后，关闭登录页无法捕获。
     - 登录页现在是唯一的登录出口。成功时待购要么被订阅页消费，要么被清除，不会在下次打开购买视图时被自动下单。
   - 删除 PremiumView 中 `vdl-login-cancelled` 的监听。
   - **订阅页恢复待购后即消费持久化记录**：
     - 现状：`continuePendingPurchase` 恢复待购后调用 `handleBuy`，但 `handleBuy` 只打开确认框。用户在确认框点取消后，存储里的待购还在，下次打开订阅页会再次弹出同一商品的确认框。
     - 改法：恢复并命中套餐 / 渠道时，先调用 `clearPendingPurchase()` 清掉持久化记录（套餐与渠道选择已在页面上），再调用 `handleBuy`。
     - 渠道失效时，也改为调用 `clearPendingPurchase()`，不再只把内存置空。

4. **升级弹窗**
   - `UpgradeModal` 删除登录判断，未登录时也一律 `emit('upgrade')`：
     - popup 宿主打开购买视图，由购买视图自身的登录门控进入登录页；
     - content 宿主由 `UpgradeModalManager` 打开官网 pricing，与现状一致。
   - 用户可见变化：popup 中未登录点升级，从「直接弹登录框」变为「先看到套餐，再点登录」。

5. **background**
   - `GoogleLoginService.start` 删除 `callerIsPopup` 参数，以及 `email_verification` 时打开登录页的分支。
   - `BackgroundMessageRouter.startGoogleLogin` 不再读 `context.tabId`。
   - Google 邮箱二次确认统一由登录页原地展开验证码步骤。
   - 保留 Google 调用的 660 秒 RPC 超时：登录页需要等待授权结果。

6. **清理**
   - `openExtensionLoginPage` 与 `buildExtensionLoginUrl` / `parseLoginPageParams` 中，不再需要的参数一并删除。
   - 例如 `verify_email` 只服务 background 转交，转交删除后，这个 URL 参数随之删除。

## UI 设计（架构师设计，执行者照此实现）

以下规格是最终结论，实施时同步到 `feat.md`「extension 插件登录页」表格，覆盖原表格。

### 布局

- 页面：
  - 背景沿用 `extension-page.css` 的 `#f8fafc`；
  - 内容水平居中，单列，距顶 `max(48px, 12vh)`，底部留 32px；
  - 列宽 `min(400px, 100% - 32px)`。
- 卡片：
  - 白底，`1px` 描边 `GRAY_100`，圆角 14px，阴影 `0 12px 32px rgba(15, 23, 42, 0.08)`；
  - 内边距 `32px 28px 24px`；
  - 窄于 400px 时内边距改为 `24px 20px 20px`。
- 卡片内自上而下：

| 序 | 元素 | 规格 |
| --- | --- | --- |
| 1 | 品牌区 | 插件图标 `icons/48.png`，显示 40×40，居中；下方 8px 是产品名，复用 `app.title`，13px / 600 / `GRAY_500`，居中 |
| 2 | 标题区 | 距品牌区 16px。主标题 `auth.modal.title` 22px / 600 / `GRAY_900`；描述 `auth.modal.description` 13px / 行高 1.5 / `GRAY_500`；两者间距 6px，均居中；标题区与下方元素间距 24px |
| 3 | Google 按钮 | 全宽，高 42px，白底，1px `GRAY_300` 描边，圆角 8px；左侧 18px 多色 G 图标，与文字间距 10px；文字 14px / 600 / `GRAY_800`；hover 时描边和文字变为 `PRIMARY`；busy 时 `opacity: 0.6` |
| 4 | 分隔线 | 上下各 20px。横线 1px `GRAY_200` 延伸至两侧，中间是 `auth.modal.or`，12px / `GRAY_500`（白底对比度 ≥ 4.5:1），左右留 12px |
| 5 | 邮箱表单 | 常驻。标签 `auth.modal.emailLabel` 12px / 600 / `GRAY_600`，与输入框间距 6px；输入框全宽、高 42px、圆角 8px、1px `GRAY_300`，14px；focus 时描边 `PRIMARY`，加 `0 0 0 3px` 的 `PRIMARY` 20% 透明度外圈；下方 12px 是主按钮 `auth.modal.continueWithEmail`：全宽、高 42px、`PRIMARY` 底、白字 14px / 600，hover 为 `PRIMARY_DARK` |
| 6 | 验证码步骤 | 发码成功后，主按钮位置换成：标签 `auth.modal.codeLabel`；一行内是验证码输入框（flex 1，`letter-spacing: 0.2em`，maxlength 6）加 `auth.modal.resend` 次级按钮（白底描边，高 42px），间距 8px；下方 12px 是主按钮 `auth.modal.signIn`。邮箱输入框保留可编辑，行为同现状 |
| 7 | 状态 / 错误 | 表单下方 10px，13px / 行高 1.5。状态文字用 `GRAY_500`；错误文字用 `DESIGN_TOKENS.RED_900`，底色 `DESIGN_TOKENS.RED_100`（对比度约 4.76:1；`COMMON_COLORS.ERROR` 配 `ERROR_BG` 仅 3.44:1，不用），内边距 `8px 10px`，圆角 6px |
| 8 | 条款 | 距上方 24px，12px / `GRAY_500`，居中；两个链接 `PRIMARY` / 600，hover 时加下划线 |

- 成功状态：
  - 替换卡片 2–8 号元素，品牌区保留；
  - 居中依次是：
    - 40×40 圆形 `SUCCESS_BG` 底，中间是 20px `SUCCESS` 色对勾（内联 SVG，`stroke-width` 2.5）；
    - 下方 16px 是 `auth.page.successTitle`，20px / 600 / `GRAY_900`；
    - 再下方 6px 是 `auth.page.successDescription`，13px / `GRAY_500`。
  - 只在 `source=popup` 时出现；购买入口直接跳订阅页。
- 无关闭按钮、无顶部导航。`MODAL_CLOSE`（`auth.modal.close`）只服务弹窗关闭按钮，随弹窗删除。
- 不新增文案 key。`auth.modal.*` 的 key 名不改，避免 14 个 locale 的无谓改动。

## 非目标

- 不改后端，不新增依赖。
- 不改 content（Vimeo 页面）升级入口仍去官网 pricing 的现状。
- 不修复「RPC 错误到页面后不是 `ApiError`，后端文案被替换成通用失败文案」这一既有问题。
- 不做登录成功后自动关页、自动 `openPopup`。
- 不做「重复点击时复用已打开的登录页」。

## 验收

1. `cd extension && pnpm check` 通过。
2. 相关单测通过。HEAD 上 `popup-toast.spec.ts` / `popup-download-queue.spec.ts` 的 4 个失败与本任务无关。
3. 按 `spec-extension.md`，用真实后端加 Playwright 加载 dev 包验证：
   1. popup 顶栏点登录，打开登录页标签页，Google 按钮与邮箱表单同时可见。截图核对「UI 设计」。
   2. 先在存储里放一条旧待购，再从 popup 顶栏登录（`source=popup`）。邮箱验证码登录成功后：展示成功状态，token 已写入，旧待购已被清除。
   3. popup 中未登录点购买，写入待购并打开登录页（`source` 为购买入口）。登录成功后，同一标签页跳到插件订阅页，并弹出该商品的确认框。在确认框点取消，关闭再重开订阅页，不再弹出旧商品。
   4. 插件订阅页中未登录点购买，当前标签页跳到登录页，登录后回到订阅页继续下单。
   5. 插件订阅页中未登录、没有待购时，点顶部登录，登录后仍回到订阅页。
   6. 填错验证码时，页面内报错。
      - 错误样式符合 UI 设计。
   7. 每条登录链路的 `login_click` / `login_success` 只各记一次，source 与入口一致。
      - 打点只发 SLS，不写后端 mark 表；默认 dev 构建没有 SLS 配置时直接跳过。
      - 验证方法：dev 构建时配置 SLS endpoint / logstore；Playwright 在 SLS 请求处记录事件与 source，计数后返回 204，再断言计数。SLS 不是项目 API，按现有 `tests/fixtures.ts` 的做法隔离。
      - Google 单测同步断言成功、取消的事件次数；取消时成功事件为零。
   8. 更新后的 `vimeo-real-download.spec.ts` 通过。
   - Google 链路依赖真实 Google 账号，Playwright 不跑。`LoginPanel` 收到 `completed`、`email_verification`（原地展开验证码步骤）、`cancelled` 三种结果时的行为，由单测覆盖。单测里只隔离 Chrome identity / RPC 返回值，不涉及项目 API。
4. 检索确认不再残留以下符号：
   - `LoginModal`、`emailEntry`、`handoff`、`callerIsPopup`、`vdl-login-cancelled`；
   - `adoptLoginSource`、`setLoginModalHostMounted`；
   - 以及被删除的 URL 参数。
5. docs 与源码一致，不残留「popup 内登录弹窗」「background 转交登录页」等旧描述。

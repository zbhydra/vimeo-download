## 验收标准

1. 页面加载后可以在浏览器 Cookie 中看到 `client_uuid`。
2. Network 面板可以看到 `/assets/icons/credits.svg` 返回 SVG,不是 JSON。
3. SVG 响应头包含 `Cache-Control: no-store`。
4. 本地 `pnpm dev` 下该图片请求通过 Vite proxy 命中本地后端;不依赖 `website/public` 静态 SVG。
5. 已建立 Redis 记录后,`send-email-code` 正常发送验证码。
6. 删除 Redis 记录或修改 IP 后,`send-email-code` 返回 `AUTH_PAGE_REFRESH_REQUIRED`。
7. 删除 Redis 记录后,`email-verify-login` 不消耗验证码尝试次数。
8. SVG 接口缺 Cookie 或 Redis 写入异常时仍返回 SVG。
9. SVG 接口内部未捕获异常被路由捕获为 404,不返回 JSON 错误。
10. 删除 Redis 记录后,`parse-pre-v2` 在 IP 限流前返回 `AUTH_PAGE_REFRESH_REQUIRED`。
11. 删除 Redis 记录后,`download-pre-v2` 在用户短锁前返回 `AUTH_PAGE_REFRESH_REQUIRED`。
12. Google 登录、订单、支付、mark-log 和解析执行节点不受影响。

## 风险与回滚

- 风险:用户换 IP 后邮箱登录被拦截。处理:提示刷新页面后重试,刷新会重新建立绑定。
- 风险:website nginx 规则顺序错误导致静态 404。处理:精确 location 必须放在通用 `.svg` 静态 location 前。
- 风险:Redis 故障导致受保护的重要 API 不可用。处理:按 fail-closed;可临时回滚对应 API 校验调用。
- 回滚:把 `config_public.device_trust.verify_device_id` 改为 `false`;保留 SVG 和 Cookie 写入不影响主流程。

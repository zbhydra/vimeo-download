# 005 · 网站下载媒体白名单执行计划

## 1. 目标

为 website Credits 下载链路增加写死在代码里的媒体白名单，降低网站域名提供高风险文件下载导致 Google 安全提示的风险。

## 3. 改动范围

### 3.1 后端

新增或调整：

- `backend/src/app/services/media_resource_token_service.py`
  - `MediaResourceTokenClaims` 增加 `mime_type: str | None`。
  - `issue_token()` 增加 `mime_type` 参数。
  - 解码旧 token 缺失 `mime_type` 时按 `None` 处理。
- `backend/src/app/services/media_provider_service.py`
  - 签发 resource token 时写入 `resource.mime_type`。
- `backend/src/app/services/media_pre_authorization_service.py`
  - `DownloadPreValidatedRequest` 增加 `mime_type`。
  - `download-pre-v2` 验签 resource token 后、扣费前执行白名单校验。
- `backend/src/app/utils/media_download_allowlist.py`
  - 写死白名单常量、风险后缀常量和判定函数。
- `backend/src/app/i18n/common_code.py`
  - 新增 `MEDIA_DOWNLOAD_FILE_TYPE_NOT_ALLOWED = 24049`。
- `backend/src/app/i18n/locales/*.json`
  - 增加后端错误码文案，前端最终展示仍使用 website i18n。

不新增数据库表、不新增迁移、不新增依赖。

### 3.2 前端

新增或调整：

- `website-shared/src/download/scripts/media-download-allowlist.ts`
  - 写死前端同口径白名单和判定函数。
- `website-shared/src/download/scripts/workspace-download.ts`
  - 单文件下载在登录和 `download-pre-v2` 前先判定。
  - Download all 构建队列时跳过非白名单资源。
  - 全部跳过时提示并滚动到插件卡片。
  - 后端返回 `MEDIA_DOWNLOAD_FILE_TYPE_NOT_ALLOWED` 时提示并滚动到插件卡片。
  - 插件卡片滚动时扣除顶部固定或粘性导航占用，避免卡片顶部被遮挡。
- `website-shared/src/download/scripts/workspace-errors.ts`
  - 识别 `24049` 并映射到 i18n 文案。
- `website-shared/src/download/schema.ts`
  - `errors` 增加 `unsafeFileTypeUseExtension?: string`。
- `website/src/i18n/schema.ts`
  - 同步 schema。
- `website/src/i18n/lang/*.ts`
  - 增加 `unsafeFileTypeUseExtension` 文案。

复用现有插件引导卡片 `data-download-large-file-extension-inline`，不新增弹窗和新组件。

## 4. 执行阶段

### Phase 1 · 共享判定口径

后端新增 `media_download_allowlist.py`：

- `WEB_DOWNLOAD_MEDIA_ALLOWLIST`
- `WEB_DOWNLOAD_DENIED_SUFFIXES`
- `is_web_download_media_allowed(filename: str | None, mime_type: str | None) -> bool`

前端新增 `media-download-allowlist.ts`：

- `WEB_DOWNLOAD_MEDIA_ALLOWLIST`
- `WEB_DOWNLOAD_DENIED_SUFFIXES`
- `isWebDownloadMediaAllowed(resource: MediaPost): boolean`

验收：

- `.mp4` 无 MIME 允许。
- 无后缀 + `video/mp4` 允许。
- `.480` + `video/mp4` 允许。
- `.pdf`、`.docx`、`.pptx`、`.xlsx` 允许。
- `.exe` + `video/mp4` 拒绝。

### Phase 2 · resource token 签入 MIME

改动：

- `MediaResourceTokenClaims` 增加 `mime_type`。
- `issue_token()` 接收并写入 `mime_type`。
- `_payload_to_claims()` 对旧 token 缺失 `mime_type` 按 `None` 处理。
- `_validate_claims()` 校验 `mime_type` 长度和形态，只做轻量字符串规范化，不因未知 MIME 拒绝 token。
- `media_provider_service._attach_resource_tokens()` 传入 `resource.mime_type`。

验收：

- 新 token payload 包含 `mime_type`。
- 旧 token 缺失 `mime_type` 不报 invalid request。

### Phase 3 · download-pre-v2 强校验

改动：

- `DownloadPreValidatedRequest` 携带 `mime_type`。
- `validate_download_pre_payload()` 从 claims 读取 `mime_type`。
- `create_media_download_pre_v2()` 在计算扣费和签发 `media_download` token 前校验。
- 不通过时抛 `AppCommonException(CommonCode.MEDIA_DOWNLOAD_FILE_TYPE_NOT_ALLOWED, ...)`。

验收：

- 非白名单不扣 Credits。
- 非白名单不写 `user_download_records`。
- 非白名单不签 `media_download` token。

### Phase 4 · 前端提示与跳过

改动：

- 单资源点击：非白名单直接显示 `unsafeFileTypeUseExtension`，弹确认框，确认后展示并滚动到插件卡片；未挂载站点确认框时用浏览器原生确认框兜底。
- Download all：过滤非白名单；剩余资源继续下载；全被过滤时显示提示并弹确认框。
- 后端 `24049`：同样显示提示并弹确认框。

验收：

- 非白名单单资源点击不触发登录弹窗。
- 非白名单单资源点击不请求 `download-pre-v2`。
- 非白名单提示弹窗出现前不滚动，取消不滚动，确认后滚动到插件卡片，且卡片不被顶部导航遮挡。
- 混合 Download all 只请求白名单资源。
- 全非白名单 Download all 不请求 `download-pre-v2`。

## 7. 风险与回滚

风险：

- 前后端白名单常量重复维护，后端为准，前端只做体验提前拦截。
- 旧页面上的旧 resource token 没有 `mime_type`，无后缀媒体可能被后端拒绝；用户重新解析后恢复。
- 上游 MIME 错误时，可能误拒绝少量资源；用户可使用插件下载。

回滚：

- 后端移除 `download-pre-v2` 白名单校验即可恢复原下载行为。
- 前端移除本地白名单校验和 `24049` 特殊映射即可恢复原体验。
- `resource_token` 多出的 `mime_type` claim 可保留，不影响旧逻辑。

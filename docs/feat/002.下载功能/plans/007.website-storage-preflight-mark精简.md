# 007 · Website 存储预检埋点精简执行计划

## 1. 目标

把 `web_download_storage_preflight_blocked` 收敛为事件专用的紧凑 JSON，删除无消费方的浏览器指纹字段和重复错误内容，并保证 `mark_msg` 始终以完整 JSON 落库。

## 3. 字段合同

容量预检阻断保留：

- `url`、`reason`、`download_mode`。
- `file_size_bytes`、`available_bytes`、`required_bytes`。
- `browser.user_agent`、`browser.device_memory`。
- OPFS 不可用时可选的 `cause.name`、`cause.message`。

删除：

- 固定值 `storage_type=opfs`、`recovery_mode=current_page`、`operation=preflight`。
- 可由事件名或保留字段推导的 `error`、`preflight_reason`、`error_name`、`error_message`、`storage_usage`、`storage_quota`、`opfs_writable`、`resource_count`。
- `vendor`、`platform`、`language/languages`、`hardware_concurrency`、`max_touch_points`、`cookie_enabled`、`online`、viewport、screen、device pixel ratio。

## 4. 改动范围

- Website 共享运行时改用存储预检专用 payload builder，并按字段优先级生成不超过 1000 字符的完整 JSON。
- SLS 继续在外层字段记录 UA、language、viewport；方案 B 的 `mark_msg` 额外保留 UA 与 device memory，不重复记录 language、viewport。
- 后端 API 在 1024 字符边界拒绝超长 `mark_msg`，service 不再静默截断。
- 管理后台下载详情同时读取新的顶层 `file_size_bytes` 和旧 `storage.file_size_bytes`。
- 更新现有 Website/Backend 测试与技术规格，不新增依赖、不修改数据库结构。

## 5. 验收标准

- 用户样例对应的 payload 是合法 JSON，长度不超过 1000。
- `hardware_concurrency`、`max_touch_points` 及其他已删除字段不再上报。
- 容量不足仍能读取 URL、原因、下载模式、文件大小、可用空间和要求空间。
- OPFS 不可用仍保留脱敏后的底层错误名与消息。
- 后端接受 1024 字符，拒绝 1025 字符，不产生截断 JSON。
- 新旧存储预检日志均可被管理后台解析。

## 7. 风险与回滚

- 仓库外的临时 SLS 查询若直接读取已删除字段，需要改为查询新的紧凑字段；正式后台没有这些字段的消费者。
- 回滚时可恢复旧 payload builder，但不得恢复后端的字符串硬截断，否则会重新产生非法 JSON。

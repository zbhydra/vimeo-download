## 1. 证据与处置规则

- `S`：已核对源码入口和可达调用链，未逐项真实复现；`O`：官方合同支持；`V`：已有真实运行证据，只覆盖原报告 §6 或本文 §5 明确的样本/步骤；`?`：样本、配置或运行触发未证明。每行的证据均不包含发生频率；所有问题频率未知，不按“常见”“低概率”推断严重度。
- 每行按“入口 → 前提 → 可达调用 → 状态/已有机制 → 实际后果”记录；恢复说明描述修复前用户/运营能做什么，不把恢复操作写成问题已解决。
- `待修复`、`待极简拒绝`、`接受限制`、`待配置`、`待证据`是处置状态。只有实现、独立审查及必要验收完成，才能改为已完成。源码条件成立与现实样本存在是两种证据，不能互相替代。
- 修复确认的所有权和调用链错误；局部错误可提示用户重试。保留既有 FIFO、typed RPC、一次重签 restart、超时、20 秒心跳及任务对账，不新增状态机框架、跨上下文锁、CAS、租约、补偿链或备用下载框架。
- 新代码禁止依赖注入（FastAPI `Depends` 除外）；不新增依赖；TS 类型依 [extension 规范](../../../references/specs/spec-extension.md) 的边界豁免；用户文案走 i18n。项目 API 请求真实本地后端，Chrome API 的纯逻辑 mock 不等于 mock 后端。

## 2. 全局实施裁决

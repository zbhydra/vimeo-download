# 扩展大文件下载模式

## 目标

参考 `docs/research/vimeo-downloader-竞品解析/source/js` 中竞品的设置与下载实现，为插件补齐：

- 备用下载方式开关；
- 自动分割模式与 0.5–8GB 阈值；
- 不分割（流式下载）模式；
- 超阈值提示、分片文件命名、队列进度与失败提示。

## 范围

包含 popup 设置、`chrome.storage.local` 设置契约、Vimeo 下载任务拆分、offscreen 流式产出、备用交付路径和对应 i18n/测试。

不包含竞品的登录、历史页、MP3 方案、远程配置体系、埋点字段迁移，也不新增后端接口。

## 已确认基线

- 竞品设置默认值：`splitMode=auto`、`autoSplitThresholdGB=1.5`、`useBackgroundBlobDownload=false`。
- 阈值合法范围为 `0.5–8GB`，步进按 0.1GB 保存。
- 自动分割按媒体估算大小与目标阈值换算时间窗，每个时间窗作为独立下载任务并带时间后缀。
- streaming 模式保持单个完整产物，使用 OPFS 流式写入；不因阈值拆分。
- 竞品源代码仅作为行为参考；实现复用仓库已有 Mediabunny、OPFS、RPC 和下载编排，不复制竞品的 wasm 资产或历史缺陷。

## 阶段与依赖

1. **设置与显示合同**：新增设置字段、默认值、边界归一化、设置弹层 radio/阈值输入、自动分割预警和所有 locale 文案。输出供下载链路读取的稳定合同。
2. **任务级自动分割与流式模式**：在真实下载入口读取设置；基于已有媒体时长、码率和分片大小估算，auto 模式超阈值时生成时间窗子任务；never 模式走不拆分的流式产出；统一队列进度、取消、失败和文件名后缀。
3. **备用交付与集成**：在现有 offscreen → background 落盘边界接入备用 Blob 保存路径，开关只改变交付方式；完成端到端设置到保存结果的接线和回归。

共享设置/任务类型先落地，后续阶段只消费该合同。涉及 `OffscreenTaskRunner` 的改动串行，避免两条交付路径各自维护状态。

## 验收标准

- 设置弹层显示截图对应的三个控制：备用下载 toggle、Auto split + 阈值、Never split streaming；刷新 popup 后设置保持。
- 阈值输入会归一化到 0.5–8GB；非法输入不会进入下载任务。
- 估算超过阈值的可分段视频显示预警；auto 模式产生带 `part`/时间范围后缀的多个可播放文件，队列每部分可取消、失败可重试。
- never 模式不生成子任务，长视频走流式 OPFS 产出；不再因 auto-split 阈值拆分。
- 备用开关关闭时保留现有交付；打开时使用备用 Blob 交付，落盘失败能按现有错误合同重试。
- 现有 progressive、字幕、封面、音频和剪辑下载行为不回归。

## 已知限制

Mediabunny 当前已安装，竞品的 libav wasm worker 未随本仓库提供；因此 streaming 的实现边界以现有 Mediabunny/OPFS 能力为准，不引入新的 wasm 依赖。若实际媒体格式无法在该边界内完成流式 remux，worker 必须在审查阶段报告阻塞，而不是静默回退为全内存路径。

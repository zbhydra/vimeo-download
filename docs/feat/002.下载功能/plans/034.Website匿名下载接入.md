## 2. 验收记录

执行日期：2026-09-17。本轮复用运行中的真实后端 `http://127.0.0.1:9600`；只读核实唯一启用节点的 public/internal 地址均为该 loopback 地址。未修改后端配置或节点状态，未使用生产 API。Playwright 使用稳定版 Chrome 和项目浏览器身份 helper，并独立启动网站开发服务器，实际项目 API 请求限定到本地后端。

本轮有效匿名配置从本地数据库读取：直接放行 2 次、免费总次数 3 次、等待 300 秒、文件须小于 314572800 字节。仅为本轮测试记录；策略真源仍为后端配置服务。用例为独立 UUID 设备通过真实 Counter 服务准备边界次数，不改资源大小或伪造接口响应。

### 命令

最终构建：`pnpm --dir website build`，通过，类型检查 0 错误／0 警告。最后仅修改文档，未重复构建。

真实用例：`website/e2e/anonymous-parse-download-smoke.spec.ts`。分场景执行以下命令模板，不是执行默认模拟后端 suite：

```bash
E2E_REAL_API_BASE_URL=http://127.0.0.1:9600 E2E_WEB_PORT=9630 \
pnpm --dir website exec playwright test --project=parse-download-smoke \
  --grep 'anonymous: 等待持久化' --workers=1 --retries=0 \
  --output=tmp/anonymous-wait-proof --reporter=line
```

保持上述本地 API 和执行参数，实际执行的筛选与输出目录如下；9631／9632 仅用于独立开发服务器端口：

- `--grep 'anonymous: 真实'`，默认 Telegram `wallsps/640`，输出 `tmp/anonymous-proof`：匿名直接放行、隐藏 Credits、proxy 文件落盘通过（**Telegram 样例与 proxy 落盘已随单平台转型失效；现行默认样例为 Vimeo `1194296700`，落盘走 direct / client_mux**）。
- 同一筛选加 `E2E_MEDIA_URL=https://x.com/yetone/status/2059751448108507277`，输出 `tmp/anonymous-direct-proof`：direct 匿名下载落盘通过。
- 同一筛选加 `E2E_FORCE_NATIVE=1`，输出 `tmp/anonymous-native-proof`：浏览器 `storage.estimate()` 返回零配额，触发既有 proxy 原生 GET fallback 并落盘。该条件是浏览器能力覆盖，不代表真实磁盘耗尽。（**`proxy` 下线后该 fallback 不再存在；`E2E_FORCE_NATIVE` 开关与零配额分支已从 `website/e2e/anonymous-parse-download-smoke.spec.ts` 删除，现行 direct / client_mux 没有 fallback，零配额预检直接阻断**）
- `--grep 'anonymous: 等待持久化'`，输出 `tmp/anonymous-wait-proof`：等待无文件请求，刷新／重复点击保留截止时间，关闭后到期不自动下载，重新点击可下载；登录窗口取消后恢复等待；Escape 后焦点返回按钮。保存桌面与 390×844 移动端截图并人工检查。倒计时到期采用浏览器受控时钟推进。
- `--grep 'anonymous: 批量'`，输出 `tmp/anonymous-batch-proof`：平台页共用工作区真实解析，授权序列先为 `[1,2]`；首文件完成后次项等待，关闭即停止。推进浏览器时钟后重新点击，序列为 `[1,1,3]`，第三项要求登录；已有文件保留，按钮可用，不显示失败或全部成功。
- `--grep 'anonymous: 等待中真实登录'`，输出 `tmp/anonymous-login-proof`：等待中提交现有邮箱登录表单，真实账号授权、余额与文件落盘通过，Credits 标签重绘。验证码写入真实 Redis，测试账号由现有 seed 模块以唯一 `example.com` 邮箱准备，不发送邮件。下载 JWT 的 `uid` 证明账号授权；运行上下文 token／owner 同步由源码审查核实。
- 同一 `anonymous: 真实` 筛选加 `E2E_MEDIA_URL=https://www.reddit.com/r/whoathatsinteresting/comments/1tp3u42/update_body_cam_footage_from_cop_who_pulled_over/`，输出 `tmp/anonymous-mux-reddit-proof`：真实解析返回 `client_mux`、9111307 字节，匿名授权及合并文件落盘通过。
- `--grep 'anonymous: proxy'`，输出 `tmp/anonymous-resume-proof`：Chrome 真实网络限速产生已提交 checkpoint 后刷新，Continue 使用非零 Range 完成文件；匿名授权总数为 1。没有伪造恢复记录或下载凭证。（**现行 e2e spec 已无该测试标题，且 `proxy` 已下线，条目失效**）
- `--grep 'anonymous: (节点网络|等待期间浏览器)'`，输出 `tmp/anonymous-refresh-proof`：两项通过。X direct 首次节点请求真实完成后中止浏览器接收，session 再授权成功，授权／节点请求均为 2 次。另一项将浏览器时间推进到真实凭证到期时间之后，重新授权时调整到原等待已结束且新凭证有效的时间；API 与签名凭证均真实，授权 2 次。仅证明浏览器判断凭证到期后的重授权，不声称服务端真实过期。

下载模式额外以只读解析确认，未重复下载：`E2E_PARSE_ONLY=1` 配合 `anonymous: 真实` 筛选，输出 `tmp/anonymous-proxy-metadata`、`tmp/anonymous-direct-metadata`、`tmp/anonymous-reddit-metadata`；其中 `api-results.json` 记录真实模式与大小。（**`anonymous-proxy-metadata` 与 Reddit 样例已失效，现行只读解析只能得到 direct / client_mux**）其他响应与文件保存在各场景输出目录。

构建和最终场景运行日志集中于 `website/tmp/anonymous-verification-logs/`；所有上述路径均为本地证据，不提交。文案检查与独立 runtime／整体审查通过。文档完成后检查相对引用、旧强制登录描述及 `git diff --check`。

### Google 真实会话补验

2026-09-17，用户授权使用当前浏览器 Google 会话补验。通过 kimi-webbridge 操作独立标签组，保留其他页面及既有登录状态；未发送邮件、购买或修改账号余额／设置。

开发服务命令：

```bash
PUBLIC_API_BASE_URL=http://127.0.0.1:9600 \
pnpm --dir website dev --host 127.0.0.1 --port 9633
```

实际步骤与结果：

1. 确认本地后端健康；在新的 `http://127.0.0.1:9633/` origin 打开工作区，保持原网站登录状态不变，为本轮设备通过真实 Counter 服务准备等待边界。
2. 真实解析 Telegram `wallsps/640`，点击下载出现匿名等待窗口；点击登录及 Google 按钮，进入真实 `accounts.google.com` 账号选择页，选择现有已登录会话。
3. 配置回调为 `http://localhost:9600/api/client/auth/google/oauth/callback`，随后回到本地 9633 页面。真实 `/auth/google/exchange`、`/auth/me` 均为 HTTP 200、业务码 `10000`；工作区恢复 3 个资源，登录态与 Credits 标签恢复，等待窗口关闭、下载按钮可用。
4. 回跳后、再次点击前的网络记录中，账号下载授权请求为 0，文件请求为 0；没有自动下载。
5. 再次点击资源下载，真实 `/media/download-pre-v2` 返回 HTTP 200、业务码 `10201`，页面正确提示积分不足，未发出 `/media/download-v2`。未给该真实 Google 账号补测试积分；账号落盘沿用已通过的真实邮箱验收证据。

WebBridge 操作使用任务会话 `website-anonymous-oauth` 的 `navigate`、`snapshot`、`fill`、`click`、`network`，没有替换 API、伪造 Google 凭证或回跳。脱敏证据位于 `website/tmp/anonymous-google-oauth-proof/`：`before-reclick-network.json`、`after-reclick-network.json` 和 `oauth-summary.json`。仅保留本地请求路径、状态码、请求数量和界面状态，不包含邮箱、账号名称、token 或 OAuth code。

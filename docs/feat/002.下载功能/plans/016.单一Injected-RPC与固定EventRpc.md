# 016 · 单一 Injected RPC 与固定 EventRpc

> **部分作废**：本计划成文于多平台时期。Instagram / X / Telegram / Threads 站点与 `website-tgd-pro`、`extension-pro` 已随单平台（Vimeo）转型整体删除，文中这些平台与站点的条目只作历史记录；现行架构以 `../tech-站点适配.md` 与 `../references/index.md` 为准。
## 1. 目标

把 content 与 MAIN world 的通信简化为一个固定 EventRpc 通道，并让下载只使用一个完整调用：

```ts
downloadMedia({ source }): Promise<{ success: true }>
```

该调用在站点下载 service 完成 fetch、必要处理并触发浏览器下载后返回。下载专用 timeout 为 24 小时，正常跟随页面生命周期；短 timeout 不能取消 MAIN handler，反而会破坏 `for...of` 顺序。调用真实抛错时 content 打印错误并继续后续项。

EventRpc 使用固定事件名，不执行密码学握手。宿主页面可以观察、伪造或阻断消息；MAIN 因此只能拥有页面本身已有的媒体查询、允许 host fetch 和文件触发能力。

## 2. 非目标

- 不增加第二个 RPC/权限通道或承载业务终态的单向下载事件；Telegram 主消息允许固定、仅改文案的瞬时进度事件。
- 本阶段不提供下载停止 API；后续 Plan 024 只为具备真实中止能力的 Telegram 来源增加独立取消方法，其他 provider 继续保持稀疏 handler。
- 不保存 MAIN 下载记录，不处理重复消息。
- 不保证页面刷新时继续执行。
- 不把 EventRpc 描述为可信通信。
- 不增加 Chrome 权限、后端接口、第三方依赖或依赖注入。

## 3. 依赖

- Plan 015：共享单项下载与 for-of 批量。

## 4. 改动范围

- 保留一个 `InjectedChannel` 和一组固定 request/response DOM 事件名。
- 删除 HMAC、nonce、challenge、proof 和动态事件名派生代码。
- register 的通用能力只保留 `downloadMedia`；删除 injected 下载批量方法。
- Instagram 在同一个 site handler 中提供 Plan 010 使用的 `getCapturedMedia` request-response；Telegram 同理只增加仍有调用方的 K/sidebar 查询方法。其他站点不声明这些方法，也不实现空 stub。
- `serve()` 只注册当前站点实际提供的方法；method allowlist 从当前 handler 的键生成。
- 每个站点 injected 入口同步安装一个 listener；停止时只移除这个 listener。
- 删除各站点 `handleBatchDownload()`，只保留单资源下载 service。
- content 复用 Plan 015 的模块级具体 `InjectedChannel` 客户端；`downloadOne` 直接 import，不接受外部 client 参数。
- request/response 在解析前检查大小，再校验基础结构和方法名；下载 source 校验字段、HTTPS、允许 host 和 MIME。
- MAIN 禁止访问 `chrome.*`、扩展 storage、登录 token、额度接口和任意后端地址。

## 5. 执行步骤

1. 先写固定事件通道、当前 handler allowlist 和非法输入测试。
2. 删除握手与动态事件名，接入固定 EventRpc。
3. 将共享下载协议缩成完整 `downloadMedia` 调用。
4. 让 Instagram 与 Telegram 在同一固定通道中组合自身查询方法，删除其他站点 stub 和所有主动 observation 事件。
5. 删除 injected 下载批量和每个站点的批量 service。
6. 删除旧的动态 task progress、全局状态 listener 和 Popup 状态推送；Telegram 主消息改用固定非可信事件直接更新本次按钮文案。
7. 复跑 Telegram A/K、Instagram、X 和固定通道恶意输入测试。

## 6. 验收标准

- [x] content 与 injected 只有一个固定 EventRpc 通道。
- [x] 代码中不存在 HMAC 握手、动态通道派生或下载业务状态事件；Telegram 固定进度事件只影响按钮显示。
- [x] 下载只有完整 `downloadMedia` 方法，没有 start/stop 或 injected batch 方法。
- [x] RPC 返回成功时，站点 service 已触发浏览器文件下载。
- [x] RPC 超时或失败会打印错误并允许上层继续下一个资源。
- [x] Instagram/X 等站点没有 Telegram stub。
- [x] Instagram/X network capture 只通过同一通道的按需响应返回，不主动向 content 推送事件。
- [x] Telegram 仍能调用当前真实使用的 K/sidebar 查询方法。
- [ ] Telegram A/K 扫描、主消息、sidebar 和真实单项下载通过。
- [x] 非法 method、过大消息、非法 source 和非允许 host 不执行 handler。
- [x] MAIN 没有扩展权限、额度或后端鉴权能力。
- [x] 没有新增依赖注入。

## 8. 失败与回退

- 页面脚本干扰固定事件导致当前页不可用时，允许用户刷新后重试，不增加认证协议。
- 本阶段不增加取消、续传或恢复流程；后续人工取消合同见 Plan 024，timeout 不能作为取消手段。
- Telegram 查询失败时修正 Telegram handler 的真实方法，不把空方法加入其他站点。
- 本阶段可整体回退固定通道改动并发布上一稳定构建；没有存储数据迁移。

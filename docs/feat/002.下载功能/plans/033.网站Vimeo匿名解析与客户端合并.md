## 2. 实施单元

### A. 后端解析与材料合同

- [x] Vimeo 使用匿名 browser_runtime，移除旧 yt-dlp 路径及缓存结构读写。
- [x] Progressive direct / DASH AVC+AAC client_mux，稳定 source_id；下载时重新捕获同一轨道材料。
- [x] reddit/vimeo 共享 file/segments 联合，Reddit 明确输出 file。
- [x] 沿用资源签名、授权和 Credits；parse/JWT 不含签名 CDN URL。
- [x] 采集及清单共用 60 秒总预算，网站节点 JSON 准备共用 70 秒；pre 接口及 proxy 建流保留 10 秒，无新增重试层（`proxy` 建流已随 proxy 下线删除）。

### B. 网站分片下载与 OPFS 合并

- [x] API 边界一次转换 camelCase，顺序下载 init/segments，CDN 使用 omit credentials。
- [x] 双轨输入及输出走本轮 OPFS 文件，逐块网络写入、按时间交错 packet、StreamTarget 背压及 position 写入。
- [x] 预检预留输入加输出空间；OPFS 不可用仅已知 ≤50 MiB 回退内存，实际字节按资源上限终止。
- [x] 完成保存复用 File object URL 与延迟 cleanup；失败只清理本轮文件。
- [x] 存储错误与资源超限分开，14 种语言去除固定 Reddit / 50MB 提示。

### C. 集成与交付

- [x] 小样例 `1196869805` 走网站输入、四个真实 API、CDN、OPFS、浏览器保存、ffprobe；输出 1,299,515 字节，H.264/AAC、626×360、12.352 秒。

### 再次授权后的大文件复验

本轮只重开本地真实后端和网站，使用正常本机出口，未改生产代码、超时或重试策略，未重跑构建、单测及其他平台。运行命令（`website/` 目录）：

```bash
E2E_REAL_API_BASE_URL=http://127.0.0.1:9600 E2E_WEB_PORT=9620 \
E2E_MEDIA_URL=https://vimeo.com/1222710784 \
pnpm exec playwright test --project=vimeo-client-mux-real --workers=1 --retries=0 \
  --output=tmp/vimeo-large-network-recheck-1526 --reporter=line
```

结果为 `1 passed (5.3m)`：四个正式 API 均 HTTP 200/code 10000；材料为双轨 segments，各 200 段且含 init。浏览器收到 400 个成功 CDN 响应，保存 MP4 为 705,458,287 字节；ffprobe 确认 H.264/AAC、2048×1080、1200.085333 秒。OPFS 同时存在三文件，累计 17,715 次写入、单次最大 2,096,590 字节；保存前删除双轨，延迟清理输出后 active=0，pageErrors=[]，没有材料刷新。

新证据独立保存在 `website/tmp/vimeo-large-network-recheck-1526/<用例子目录>/`：`download.mp4`、`evidence.json`、`api-evidence.json`、`final-storage-evidence.json`、`complete.png`；`ffprobe-result.json` 转录本轮测试已有 ffprobe 输出，未重复运行。诊断记录的 305 个 `ERR_ABORTED` 请求事件没有阻止本次完整保存，不据此将成功轮判为 CDN 下载失败。

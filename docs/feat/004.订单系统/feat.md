## 定位

订单系统是**统一付费履约事务框架**:它管"每一次扣款 + 一次履约"的事务,不管"卖什么"。自动续费订阅的长期协议在 provider 侧,但每次首期/续费扣款都必须落一条 `orders`。

- 卖什么的定义在各自域:积分包到账数量与档位在 `@../003.积分系统/feat.md`;插件订阅商品与权益在 `@../006.订阅系统/feat.md`。
- 本域提供统一下单、支付渠道对接、webhook 回调、订单状态流转、履约、重复回调幂等、履约失败补偿重试、价格校验与快照能力。
- 下载本身不触发订单,订单不碰下载链路。

## 功能目标

为付费商品(积分包、订阅首期、订阅续费)提供一条统一的购买/扣款事务链路:

1. 用户在前端选择付费商品并下单;自动续费的后续扣款由 provider webhook 触发服务端创建续费订单。
2. 后端按商品类别校验价格并生成订单快照,挂接到对应支付渠道。
3. 用户在支付渠道完成付款,渠道通过 webhook 通知后端。
4. 后端校验回调、抢占订单状态、在同一个事务内完成业务履约(如积分加余额)。
5. 履约中途失败时由补偿任务重试;履约前所有环节允许局部出错让用户重试。

## 功能范围

### 包含

- 统一下单接口:接收商品类别、商品标识、支付方式和客户端当前看到的价格字段,后端校验后生成订单快照。
- 订单状态机:待支付 → 已支付 → 已取消 / 已退款;`已过期` 是预留状态,当前不由自动任务写入。履约回调状态机:未回调 → 处理中 → 成功 / 失败。
- 支付渠道对接由各渠道 provider 与回调合同维护;渠道配置走配置表。Credits 可选渠道见积分购买合同,订阅可选渠道见[订阅商品与渠道价格合同](../006.订阅系统/tech-订阅商品与状态.md#商品与渠道价格)。
- webhook 回调校验:webhook 密钥校验、金额与币种一致性校验、订单状态合法性校验。
- 订单状态查询、订单列表、未完成订单(可见期内可继续支付)查询、手动取消待支付订单。
- 履约事务:支付成功后在同一事务内把订单置为履约成功并调用对应商品域的发货能力(如积分加余额)。
- 重复回调幂等:首次成功后重复 webhook 不重复发货。
- 履约失败补偿:已支付但履约未完成的订单由定时任务小批量重试。
- Feishu 告警:付费订单履约成功、履约失败时异步通知运维,包含用户、时间、商品、金额、渠道与订单号。
- 价格校验与快照:下单时校验客户端价格是否过期,订单最终金额/币种/商品名以校验后的后端配置为准;已创建订单不受后续配置变更影响。
- 订单过期机制:订单创建时设置过期时间(默认 30 分钟),过期只影响客户端未完成订单列表可见性,不阻止已进入支付流程的回调完成。
- Bot 购买成功消息回跳:支付履约成功后给付款人发送带返回网站按钮的消息。
- 支付等待界面反馈邮箱:下单响应回带反馈邮箱,供前端在等待支付页展示。

### 域边界事实

- 订单系统只管"一次扣款 + 履约的事务"。具体商品定义、到账能力在各自域。
- 履约给用户加 Credits 时,本域只调用积分域的"加余额"能力,不实现 Credits 模型(见 `@../003.积分系统/feat.md`)。
- 自动续费的长期协议不塞进订单表;但首期扣款和每次自动续费扣款都落 `orders`。
- 支付回调只证明付款成功,不直接发货;发货由本域在履约事务内统一编排。

## 现状说明

- 当前订单完整闭环支持积分包商品;新的 Unlimited Download 首期和续费也走同一订单履约模型。
- website 的 Credits 和订阅购买弹窗按 `clink`、`paypal` 的优先级默认选中可用渠道(`DEFAULT_ORDER_PAYMENT_METHODS`);均不可用时选择配置中的首个渠道。订阅渠道以[订阅商品与渠道价格合同](../006.订阅系统/tech-订阅商品与状态.md#商品与渠道价格)为准。
- 订单履约补偿任务已上线,每 60 秒小批量扫描滞留订单重试。

## 业务流程

### 主流程(购买闭环)

1. 用户在前端选择付费商品。商品卡展示商品默认价;Credits 的支付方式按钮只展示方式名称和短说明,订阅支付弹窗展示所选渠道实际结算价。
2. 前端按商品类别与选中支付渠道,把商品标识、支付方式和所选渠道价字段原样提交给统一下单接口;商品默认价不参与验价。
3. 后端按商品类别分发到对应业务域校验(积分包 → 积分域;订阅 → 订阅域),读取当前后端配置,比对客户端价格。
4. 价格一致时后端按配置生成订单快照(商品名、最终金额、币种、支付方式),写入订单。
5. 后端调用所选支付渠道 provider 创建支付入口并保存到订单。
6. 后端读取公共配置的反馈邮箱,非空时随下单响应回给前端。
7. 前端在新标签页打开支付入口,展示支付等待界面并按固定间隔轮询订单状态。
8. 用户在支付渠道完成付款;后端通过该渠道的回调或查单流程确认结果。
9. 后端校验 webhook / capture 结果、订单存在、状态为待支付、币种与金额一致。
10. 后端把订单 CAS 置为已支付、履约回调置为处理中,记录渠道流水号、付款人渠道 UID、原始支付快照。
11. 后端在同一事务内抢占履约状态为成功,并调用对应商品域的发货能力(如积分加余额)。
12. 履约成功后,前端轮询到订单支付成功且履约成功,刷新对应域状态(例如积分余额)。
13. 后端异步发送 Feishu 成功告警,包含用户、支付/履约时间、商品、金额、渠道和订单号。

### 异常流程

- 价格过期:客户端提交的价格与后端当前配置不一致时,下单接口返回价格已更新;前端重新拉取商品配置整体刷新,用户再次确认。
- 支付网关失败:支付入口创建失败时,已创建订单不额外取消,前端提示支付网关失败,用户稍后重试。
- 用户关闭支付等待界面 / 刷新页面 / 离开页面:只停止前端轮询,不取消后端订单;Credits 购买入口不恢复 pending 订单。
- 用户重复点击购买:每次都创建新订单,不复用旧待支付订单;支付成功以回调为准。
- webhook 重复到达:首次成功后的重复回调按幂等成功处理,不重复发货。
- 订单已支付但履约卡住:订单保留已支付 + 履约处理中,由补偿任务重试(见下)。
- 履约确定性失败(如商品快照损坏):订单置为履约失败,异步发送 Feishu 失败告警,进入人工排查,不自动重试;补偿任务不扫已明确失败后又被人工置回的订单时仍按状态机判断。
- 支付成功后下载失败:不退款。
- 订单超过可见期:从未完成订单列表消失;但已进入支付流程的回调仍允许完成。
- PayPal 回跳 cancel:页面调用现有取消订单接口把本地待支付订单置为取消,原购买弹窗轮询到 `CANCELLED` 后提示取消并允许重新购买。
- PayPal success 回跳未发生或 capture 失败:前端继续轮询原订单,等待 PayPal webhook 兜底;轮询超时只提示稍后刷新 / 联系支持,不直接判定支付失败。

### 履约补偿分支

- 补偿任务每 60 秒小批量扫描已支付但履约未完成的滞留订单,重新调用订单侧履约入口。
- 履约内部用"履约状态 CAS"保证不重复发货;同一订单被多个处理者抢占时只有一个能成功。
- 确定性业务错误把订单置为履约失败,进入人工排查;运行时异常(锁、连接、超时)保留履约处理中,等待下轮重试。
- 不存在"履约失败自动恢复"逻辑,避免在发货结果不确定时重复发货。

## 非功能性需求

- 不新增第三方依赖;不新增依赖注入(api 层可用 Depends)。
- 支付成功后不支持退款;失败让用户重试,履约失败走补偿任务或人工排查。
- 错误信息必须能定位到具体用户、订单、商品、支付方式与渠道流水号。
- 不做金融级对账;渠道流水与原始支付快照写入订单表,不建独立支付流水表。
- 支付渠道配置与商品配置必须走配置表,不允许写死在前端或代码里。
- 配置读取有内存缓存(默认 3 分钟);后台改价后缓存过期前可能继续按旧配置下单,已创建订单不受配置变更影响。
- 服务器使用系统时区;按天结算以 0 点为界(订单系统本身不按天结算,但与订阅周期计算配合时遵循此口径)。
- 文字需 i18n。
- webhook 注册必须是一次明确的人工运维操作,服务启动脚本不自动注册:PayPal webhook 在 PayPal Developer Dashboard 注册到业务 API 公网地址。

## 验收标准

产品视角的关键验收(技术层验收见各 `tech-*.md`):

- 积分包商品能通过统一下单接口购买,走积分域价格校验与履约。
- 商品卡必须使用商品默认展示价;订阅支付弹窗选择渠道后显示渠道实际结算价。
- website Credits 购买按上述渠道优先级默认选择,用户可以切换可用渠道;不展示渠道价。
- 下单时后端必须校验客户端提交的所选渠道价;不一致时返回价格已更新,前端整体刷新配置。
- 订单最终金额、币种、商品名以后端校验后的配置快照为准,不信任客户端传值。
- 支付成功且履约成功后,积分余额立即生效,前端刷新对应域状态。
- 支付成功且履约成功后,后端异步发送一条 Feishu 成功告警,告警包含用户、时间、商品、金额、渠道与订单号。
- 重复 webhook 回调不重复发货。
- 履约卡住的订单会被补偿任务在 60 秒级别内重新处理。
- 履约失败或履约超时时,后端异步发送一条 Feishu 失败告警,告警包含失败原因和错误信息。
- 订单过期只影响未完成订单列表可见性;已进入支付流程的回调即使超过可见期也允许完成。
- 用户关闭支付等待界面不取消后端订单;Credits 入口不恢复 pending 订单。
- 用户可手动取消自己的待支付订单;已支付、已取消、已退款订单不能取消。
- 支付等待界面在反馈邮箱非空时展示邮箱,为空时不展示。
- PayPal success 回跳页会按 3 秒间隔轮询本地订单状态,cancel 回跳页会通知原购买弹窗;支付成功只认 PayPal webhook 后端 capture / completed 写入后的订单状态,任何路径都不能绕过订单状态直接展示到账成功。
- 支付渠道密钥(client secret、webhook secret)不出现在服务启动脚本、环境变量透传、日志或进程参数里。
- webhook 请求头密钥缺失或不一致时回调验签失败,不触发履约。

## 用户操作逻辑与 UI 元素

> 订单系统的购买 UI 服务 pricing 页的 Credits 与 Unlimited 首期订单。自动续费的后续扣款没有用户 UI,由 provider webhook 创建续费订单。

### 积分包购买入口(website 购买弹窗)

积分包购买的弹窗组件、商品卡片、协议勾选、状态机在积分系统域(`@../003.积分系统/feat.md`);本域只约定订单事务相关行为:

| 元素 | 形式 | 行为 |
| --- | --- | --- |
| 商品确认支付按钮 | 支付方式确认页主按钮 | 协议勾选且已选支付方式后可点;每次点击都创建新订单 |
| 支付方式行 | radio 行按钮 | 在已选商品下选择可用支付渠道;按上述渠道优先级默认选择;不展示渠道价格 |
| 支付状态区 | 文本 + 状态标签 | 展示待支付 / 支付成功 / 失败 |
| 手动刷新按钮 | 次按钮 | 立即请求一次订单状态 |
| 反馈邮箱行 | 文本 + mailto 链接 | 下单响应邮箱非空时在待支付 / 失败态展示;为空时整行隐藏 |
| success 态到账面板 | 文本 + check 图标 | 展示到账积分数量与刷新后的最新余额 |

积分包购买不展示未完成订单列表、不展示取消订单、不支持恢复上一次待支付订单;用户关闭 / 刷新 / 离开页面后丢弃当前订单,下次重新购买。

### 共用订单状态展示规则

- 订单状态与履约回调状态都是整数枚举,前端只按数字判断。
- 订单已支付但履约处理中:继续短时间轮询并提示"支付已确认,正在开通"。
- 订单已支付但履约失败:停止轮询,提示"支付已确认,开通异常,请联系支持",保留订单号。
- 订单已取消 / 已退款:停止轮询,刷新列表,允许重新购买;`已过期` 当前是预留状态,不会由自动过期任务写入。
- 订单不存在:停止轮询,提示重新创建订单。
- 认证失效:停止轮询,清理登录态,打开登录弹窗。

### Bot 回跳与购买成功消息

- 履约成功且非重复回调时,Bot 给付款人发送购买成功消息,消息按钮返回网站首页继续下载(不再带订单号回跳 pricing)。
- 消息语言按订单创建时保存的客户端语言返回;缺失时默认英文。

## 数据埋点

订单购买闭环的通用埋点口径,事件名是产品规格,埋点失败不得影响购买。

### pricing_* 事件口径

`pricing_*` 事件由新 pricing 页重新启用,用于 Credits 一次性购买与 Unlimited 自动续费订阅。完整事件定义见 `@../011.Pricing页/feat.md`;本域只保留订单相关字段口径。

| 事件 | 触发时机 | 关键字段 |
| --- | --- | --- |
| `pricing_checkout_configs_loaded` | checkout config 加载成功 | `available_count` |
| `pricing_checkout_configs_failed` | checkout config 加载失败 | `error_code`、`message` |
| `pricing_plan_click` | 用户点击付费方案 | `product_id`、`login_state` |
| `pricing_order_create_start` | 发起创建订单 | `product_id`、`payment_method` |
| `pricing_order_create_success` | 创建订单成功 | `order_no`、`product_id`、`amount`、`currency` |
| `pricing_order_create_failed` | 创建订单失败 | `product_id`、`error_code` |
| `pricing_invoice_open` | 打开支付入口（Clink 收银台 / PayPal 审批页） | `order_no` |
| `pricing_order_paid` | 轮询确认支付并履约成功 | `order_no`、`product_id` |
| `pricing_order_pending_timeout` | 前端等待超时 | `order_no`、`last_order_status`、`last_callback_status` |
| `pricing_order_fulfillment_failed` | 支付成功但履约失败 | `order_no` |

### 通用购买埋点建议

所有付费订单复用 `order_no`、`product_id`、`payment_method`、`amount`、`currency` 字段;订阅订单额外快照购买时商品的续费方式、商业周期与渠道续费标识。

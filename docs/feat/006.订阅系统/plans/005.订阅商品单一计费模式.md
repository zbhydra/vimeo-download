# 005 · 订阅商品单一计费模式

> 状态:已完成。代码与维护文档已收敛;本文只记录实施范围和验收状态,不声明目标环境已经部署。

## 目标

将订阅计费配置收敛为商品决定当前模式、周期和默认展示价,渠道价格决定实际结算价及自动续费能力。一个商品同一时刻只有一种计费模式和一个周期。

- 商品、渠道价格、checkout、下单保护、订单快照与履约:[`006 · 订阅商品与状态`](../tech-订阅商品与状态.md#商品与渠道价格)。
- Pricing 展示与交互:[`011 · Pricing 页与订阅配置`](../../011.Pricing页/tech-pricing与自动续费.md#商品与渠道价格)。
- 通用订单验价与快照:[`004 · 支付与履约`](../../004.订单系统/tech-支付与履约.md#3-价格校验与订单快照check_product)。

## 不包含

- 同一商品同时销售多种模式或周期;不同周期使用不同 `product_id`。
- offer、商品分组、模式切换 UI、升级、降级、多份订阅或站内取消。
- 修改历史订单、历史订阅期限或已有渠道协议。
- 兼容部署前创建、部署后付款的旧订单快照。

## 文档验收

- 维护中的产品与技术文档不再把价格行的 `auto_renew / period`、四维唯一键或同渠道多选项描述为当前合同。
- 商品默认展示价与渠道实际结算价各有唯一 owner,其他页面只保留自身差异或精确链接。
- 配置 runbook 不保存生产商品 ID、金额、密钥或 SKU,写命令可重复执行且不会意外覆盖 PayPal/Clink 已验证 SKU。

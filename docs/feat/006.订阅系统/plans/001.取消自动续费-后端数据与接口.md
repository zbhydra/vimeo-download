## 目标

后续让已购买 Unlimited 的用户在站内停止下一次自动扣款,当前周期权益保留到 `expires_at`。

## 依赖 plan

无。`002.取消自动续费-Pricing前端与验证.md` 依赖本 plan 的接口和响应字段。

## 已确认口径

- 取消只停止下次扣款。
- 不退款、不立即降级、不缩短 `expires_at`。
- 已取消续费但尚未到期时不能再次购买;到期后可重新购买。
- 到期前恢复自动续费不做。
- 不能从当前商品配置判断订阅实例的购买方式;只读取实例 `auto_renew`、渠道取消句柄和最近一次确认取消时间。
- 用户在支付平台后台取消时,本站可能收不到通知;站内取消接口需要能把渠道“已取消”结果同步回本地。
- 本站不维护渠道实时自动续费状态;`cancelled_at` 为空不保证渠道仍会扣款。

## 方案取舍

| 方案 | 结论 | 原因 |
| --- | --- | --- |
| 只跳转用户去 PayPal/Clink 自行取消 | 不选 | 实现最轻,但站内状态无法确认,用户体验差 |
| 站内调用渠道取消,本地只存最少渠道引用 | 选中 | 满足用户目标,不引入账单中心和金融级流水 |
| 新建完整 billing subscription 表和事件表 | 不选 | 过度设计;当前只有一个 Unlimited 月订阅 |

## 外部事实

- PayPal 使用 Subscriptions API cancel: `POST /v1/billing/subscriptions/{id}/cancel`。
  来源: https://developer.paypal.com/docs/api/subscriptions/v1/#subscriptions_cancel
- Clink 使用 `POST /subscription/{id}/cancel`,请求包含必填 `reason` 和 `cancelImmediately=false`,在当前账期结束时取消。
  来源: https://docs.clinkbill.com/api-reference/endpoint/cancel-subscription
- Telegram Stars 是否自动续费由商品渠道价格配置决定;即使启用,本期也不进入站内取消流程,用户仍在 Telegram 客户端管理订阅。

## 后端设计

数据表字段、类型、默认值和状态计算均直接采用 `@../tech-订阅商品与状态.md` 的“用户当前订阅”合同,本计划不维护第二份字段表。

接口:

```text
POST /api/client/subscription/cancel-auto-renew
```

流程:

1. 登录用户读取当前 `user_subscriptions`。
2. 无未过期 Unlimited 返回 `INVALID_REQUEST`,data.reason=`no_active_subscription`。
3. 实例 `auto_renew=0` 返回 `INVALID_REQUEST`,data.reason=`cancel_not_available`。
4. `cancelled_at` 不为空时幂等返回当前订阅状态。
5. 缺少渠道引用返回 `INVALID_REQUEST`,data.reason=`cancel_not_available`。
6. `paypal`: 调 PayPal cancel,传固定服务端 `reason`。
7. `clink`: 调 Clink cancel,传固定服务端原因和 `cancelImmediately=false`。
8. 渠道成功或明确返回已经取消 / 非自动续费状态时,更新 `cancelled_at=now`。
9. 返回当前订阅状态。

履约补充:

- 首期自动续费履约写入订阅实例与渠道字段,初始 `cancelled_at` 为空。
- 只有已验证的新付款把 `expires_at` 推进到更晚时间时才清空 `cancelled_at`;重复投递旧事件不得恢复自动续费展示。
- 历史实例字段允许为空且不回填。站内取消只适用于具备自动续费实例和完整渠道引用的订阅;缺失渠道引用时不从当前商品或价格配置推断,允许用户走渠道侧或支持处理。

## 验收标准

当前不执行验收。恢复实现时按以下标准验收:

- 有效 Unlimited 取消后 `expires_at` 不变。
- 取消成功后订阅状态返回 `auto_renew=false,cancel_at_period_end=true`。
- 本地已取消、渠道侧已取消时都幂等成功。
- 无有效订阅、缺渠道引用、渠道失败都有明确错误 data.reason。
- PayPal 和 Clink 都有 provider 取消方法和失败映射。
- PayPal 取消请求包含固定的非空 `reason`。
- Clink 取消请求固定 `cancelImmediately=false`,取消后当前 `expires_at` 不变。

## 风险与回滚

- 暂缓期间用户仍需到 PayPal / Clink 等支付渠道侧取消自动续费。
- 渠道取消成功但本地更新失败:用户不会再被扣款,本地仍可能显示可续费;用户可重试或人工修正。
- 本地更新成功但渠道调用失败必须禁止发生;实现顺序固定为先渠道成功再写本地。
- 回滚取消接口时无需回滚订阅实例字段;需要恢复续费只能让用户到期后重新购买。

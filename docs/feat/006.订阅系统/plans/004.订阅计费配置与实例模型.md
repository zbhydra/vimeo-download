## 目标

## 实施内容

渠道价格维度涉及:

- 配置 Model、读取 Service、支付配置快照键和结构同步。
- checkout-configs 返回的每个渠道购买选项,以及创建订单时提交的 `auto_renew / period`。
- 订阅域按 `(product_id,channel_code,auto_renew,period)` 重新验价,订单快照保存命中的购买选项。
- website 与 Extension Pro 的渠道选择合同;当前只配置每渠道一个选项时,界面不需新增套餐升级交互。

`user_subscriptions` 实例字段与订单成功和产品履约在同一事务内写入,并保留单语句原子续期,不新增锁或独立订阅状态机。

`user_subscriptions` 的新增列全部以 `NULL DEFAULT NULL` 同步到现有表。历史订阅不回填、不修复、不回放订单,原 `expires_at` 保持不变;只有新履约显式写入适用的实例字段。

## 验收口径

验收至少证明:

- 同一商品和渠道可同时存在一次性月套餐与自动续费月套餐,金额与 `provider_sku` 互不覆盖。
- `auto_renew=0` 的 `month / quarter / year` 分别增加 1 / 3 / 12 个自然月,购买日在 29 / 30 / 31 日且目标月份不存在该日期时取目标月份最后一天。
- 月 / 季 / 年自动续费选项可独立验价并创建渠道订阅。
- `auto_renew=1` 的权益时间只使用 Provider 归一化后的渠道真实账期,回调缺少完整账期时查询渠道订阅,不按本地 `period` 推算。
- Telegram Stars 的 `auto_renew=0,period=month` 不发送原生订阅参数,付款成功后按快照 `period` 发放一个自然月的一次性权益。
- 用户订阅实例能区分本地 `expires_at` 与渠道 `current_period_end_at`,好评赠送不会被渠道账期覆盖。
- 非空 `user_subscriptions` 表可一次结构同步新增全部 nullable 字段;历史行新增字段均为 `NULL`,`expires_at` 不变,仍返回 `unlimited / month / auto_renew=false`。
- 新的一次性和自动续费履约显式写入各自适用的实例字段,不依赖数据库默认值补业务事实。
- 未配置新购买选项时,当前单一 Unlimited 购买和权益行为不变。

## 官方证据

- PayPal 支持 `DAY / WEEK / MONTH / YEAR` 计费周期,Plan 变更需求见 [PayPal Subscriptions API](https://developer.paypal.com/docs/api/subscriptions/v1/) 和 [Upgrade or downgrade a subscription](https://developer.paypal.com/subscriptions/tiers)。
- Clink recurring Price 支持 `week / month / quarter / half_year / year / custom`,且官方要求 `quarter / half_year` 由平台处理、商户不得自行换算;当前账期读取 Subscription 的 `recurringInvoiceItem.periodStart / periodEnd`,见 [Clink Subscriptions](https://docs.clinkbill.com/subscriptions) 和 [Get Subscription](https://docs.clinkbill.com/api-reference/endpoint/get-subscription)。
- Telegram Stars 只在显式传入 `subscription_period` 时创建原生订阅,正式环境当前固定为 30 天,见 [Telegram Bot API createInvoiceLink](https://core.telegram.org/bots/api#createinvoicelink)。

# Google SEO 内容规范

> 适用于项目内需要被搜索引擎收录的工具页、文章页、商业页、公司页和法律页。产品范围、页面职责与技术实现由对应 `docs/feat/` 文档和运行时源码定义；本文只规定 SEO 内容质量与交付契约。

## 1. 最高原则

**准确满足用户搜索意图，高于关键词覆盖和形式指标。**

- 内容必须帮助用户完成搜索任务，不为字数、关键词密度或结构化数据制造填充内容。
- 对外文案使用目标市场的自然语言，项目文档与决策记录使用简体中文。
- 当前能力与计划能力必须分开。未在运行时实现的需求只能标为待实施，不得写成线上事实。
- 无法核实的功能、价格、额度、时效、统计、评价、案例和竞品结论不得写成断言。

## 2. 事实与证据

### 2.1 项目事实

按以下方式核实事实：

1. 用户在当前任务中明确确认的事实与决策。
2. 当前运行时源码、配置、构建产物和真实页面，用于确认已经上线的行为。
3. 当前有效的 `docs/feat/` 产品与技术文档，用于确认目标状态、页面职责和实施边界。
4. 可追溯的项目调研、测试记录和页面级 `page_seo.md`。

源码与目标文档不一致时，同时记录“当前行为”和“待实施目标”，不得自行选择一方伪装成完整现状。历史计划、快照和旧文案只能作为线索，不能覆盖当前事实。

### 2.2 外部证据

- GSC、GA4 和 SERP 结论必须记录资源或查询、市场、日期范围、维度、筛选器、读取日期和实际覆盖范围。
- 页面维度不能证明具体 query 表现；全站 query 不能直接归因到某一页面。
- 无法取得完整 Top 10 时写明实际结果数，不得声称完成 Top 10 调研。
- 引用第三方数字、案例或结论时记录可访问来源和日期。没有来源时删除该断言或改为不依赖数字的准确描述。
- 禁止创作看似真实的统计、客户案例、评价、排名、搜索量或“行业观察”来补足证据。

## 3. 内容工作区

SEO skill 默认使用仓库相对目录 `docs/seo-skill/`。用户可以在任务中指定其他 `SEO_WORKSPACE`；指定后所有产出均以该目录为根，不要求项目存在固定的产品说明文件或模板目录。

```text
SEO_WORKSPACE/
├── README.md
├── QA.md
└── {slug}/
    ├── page_seo.md
    ├── {source-locale}.md
    └── {target-locale}.md
```

`page_seo.md` 至少记录：

- slug、运行时路由、页面类型、核心搜索意图、页面目标和主要转化动作。
- 源语言、目标市场、目标 locale、`x-default` 和各语言状态。
- 已确认产品事实，以及当前行为与待实施目标的差异。
- GSC、SERP、研究、数字和案例的来源、日期、口径与限制。
- Title、Meta Description、H1、内链、结构化数据和媒体决策。
- 源语言确认记录、母语审校状态、运行时同步状态和真实页面验证状态。

locale 文件名使用项目实际采用的 BCP 47 标签，例如 `en-US.md`、`zh-CN.md`。不得强制转换大小写导致文件名与运行时 locale 不一致。

工作区是内容决策与实施输入，不是运行时自动数据源。只有源码同步、构建通过并验证真实页面后，才能将页面标记为已发布。

## 4. 页面定位

动笔前先确认页面类型，不把所有页面套进工具页或博客页模板：

| 页面类型 | 主要用户任务 | 内容重点 |
| --- | --- | --- |
| 工具/落地页 | 立即完成下载或其他操作 | 首屏任务入口、适用范围、步骤、限制、失败恢复、FAQ |
| 信息/文章页 | 学习、排障、比较或决策 | 尽早给出答案、完整任务链路、证据、相关工具入口 |
| 商业页 | 理解价格、权益或购买方式 | 当前方案、计费边界、支付方式、限制、退款或支持入口 |
| 公司/联系页 | 核实主体或获得支持 | 真实身份、服务范围、有效联系方式和响应边界 |
| 法律页 | 理解权利、义务和数据处理 | 完整、准确、可定位的条款，不用营销关键词破坏法律表达 |

每页只确定一个主要搜索任务和一个主要转化动作。相关次要需求用于补全任务链路，不得把多个无关关键词拼成一页。

## 5. 内容质量

- 尽早回答核心问题，删除对完成任务没有帮助的铺垫和重复段落。
- 每个卖点必须由可核实事实、具体步骤、明确边界、真实对比或来源支撑；禁止单独使用“快速”“简单”“专业”“无限制”等空泛形容词。
- 操作型内容覆盖前置条件、步骤、支持范围、权限边界、常见失败、恢复方式和下一步。
- 价格、Credits、支付渠道、退款和权限等高影响事实必须与当前产品来源逐项对账。
- 页面之间使用描述性锚文本建立自然内链。只在确实帮助用户继续任务时互链，不为凑链接数量制造无关入口。
- CTA 必须准确描述点击后的动作，不承诺页面或产品无法完成的结果。

## 6. 元数据与页面结构

- 每个可索引页面具有唯一且准确的 Title、Meta Description、canonical 和唯一 H1。
- Title、Meta Description 与 H1 服务不同展示场景，可以不同；三者必须表达同一页面目标。差异较大时在 `page_seo.md` 记录原因。
- 核心关键词自然出现在适合的位置，不要求固定次数，不使用关键词堆砌。
- Title 和 Meta Description 的长度以目标市场 SERP 可读性为准。字符阈值只作为检查提示，不作为牺牲准确性的硬约束。
- H2/H3 按语义逐级组织，不为字号跳级，不用多个 H1。
- slug 保持短、稳定、可读；已发布 URL 变更时同步设计 301、canonical、内链、sitemap 和 `hreflang` 迁移。

## 7. 多语言与本地化

- 先完成并确认源语言，再创建或优化本地化版本。源语言事实或结构变化后重新检查所有 locale。
- 每个 locale 明确主要市场。关键词、语序、CTA、单位、日期、称谓和示例按当地习惯改写，不逐字翻译。
- 所有语言共享产品事实和权限边界；允许用户顾虑、例子和内容详略随市场变化。
- `hreflang` 覆盖当前页面实际存在且允许索引的语言版本，并包含自指与页面确认的 `x-default`。
- 没有当地 SERP 研究、母语审校或真实页面验证时，将对应状态标为待确认，不得标记为已发布。
- RTL 语言必须验证 `dir="rtl"`、布局镜像和双向文本显示。

## 8. 媒体、性能与可访问性

- 内容图片使用描述性文件名和准确 alt；装饰图片使用空 alt，不把关键词塞入无关图片。
- 图片、视频和 iframe 声明稳定尺寸或宽高比，首屏关键媒体优先加载，非首屏媒体延迟加载。
- 正式页面不得使用 Tailwind Play CDN 或其他浏览器运行时 CSS 编译方案。
- 字体使用系统栈或同源自托管；脚本不得同步阻塞首屏渲染；第三方脚本按必要性延迟加载。
- 以真实移动端页面验证文本换行、控件可用性、LCP、INP 和 CLS，不用静态文案文件代替页面验证。

## 9. 索引与结构化数据

- 只有应该公开且内容完整的页面才允许索引，并纳入正确站点的 sitemap。
- canonical、robots、sitemap 和 `hreflang` 必须指向真实可访问 URL，不得混用不同站点域名。
- 结构化数据只声明页面可见且当前真实存在的实体、功能和内容。
- 页面没有对应可见内容时不添加 `FAQPage`、`HowTo`、`Article` 或价格 `offers`；缺少字段时省略不适用结构，不写 TODO 或占位值。
- 结构化数据类型由页面职责决定，不要求所有工具页或文章页机械包含同一组 schema。

## 10. 工作流程

1. 核实页面事实、搜索意图、目标市场和当前运行时状态。
2. 读取可用 GSC/GA4，研究目标市场 SERP，并记录证据限制。
3. 在 `page_seo.md` 建立策略、事实表和实施状态。
4. 完成源语言内容，执行事实、结构、元数据、内链和 schema 检查。
5. 取得用户对源语言的明确确认。
6. 逐 locale 研究和本地化，记录母语审校状态。
7. 用户要求实施时同步运行时源码，执行构建、产物扫描和桌面/移动端真实页面检查。
8. 回写最终状态，区分内容已完成、代码已同步、构建已通过和线上已验证。

## 11. 单页验收清单

- [ ] 页面目标、主要搜索任务、页面类型和主要转化动作明确。
- [ ] 所有产品事实、数字、案例和外部结论均可追溯，无虚构或过期断言。
- [ ] Title、Meta Description、H1、正文和 CTA 表达同一页面职责。
- [ ] 正文覆盖用户完成任务所需的信息，无关键词堆砌和空泛填充。
- [ ] canonical、robots、sitemap、内链、`hreflang` 与实际路由一致。
- [ ] 结构化数据与可见内容一致，不含占位或未实现能力。
- [ ] 各 locale 的市场、关键词、审校和发布状态记录完整。
- [ ] 工作区、源码、构建和线上状态没有混写。
- [ ] 实施任务已完成项目要求的构建与桌面、移动端真实页面验证。
